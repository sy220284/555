# DeepSeek Harness

DeepSeek Harness（`dsh`）是一个面向智能体应用的可组合运行框架。

它提供从模型调用、上下文组装、工具执行、会话持久化，到文件系统、终端、代码执行、网页访问、子智能体、工作流和图形界面的完整运行链路。

项目建立在 Cordis 插件系统之上，核心设计原则是：

> **运行时中的主要能力均可通过插件组合、替换和扩展。**

模型、工具、智能体循环、会话系统、沙箱、文件系统、网页能力乃至界面功能，都通过明确的能力接口和插件注册机制接入。

本仓库以源码开发、二次开发和架构研究为主要用途。

---

## 项目定位

DeepSeek Harness 并不是单纯的模型聊天客户端。

它更接近一套完整的 **智能体运行平台**：

```text
用户 / 外部程序
       │
       ▼
 Web / CLI / SDK / ACP
       │
       ▼
   智能体运行层
       │
       ├── 上下文与系统提示词
       ├── 模型调用
       ├── 工具调度
       ├── 人机交互
       ├── 会话与状态
       └── 智能体循环
       │
       ▼
    能力插件层
       │
       ├── 文件系统
       ├── Shell / 终端
       ├── 代码运行
       ├── LSP
       ├── 网页搜索与抓取
       ├── MCP
       ├── 技能系统
       ├── 子智能体
       ├── 后台任务
       ├── 工作流
       └── 沙箱
       │
       ▼
  本机 / 隔离环境 / 外部服务
```

这种结构允许开发者在不重写核心循环的情况下，更换模型、执行环境、工具实现或交互界面。

## 核心特性

### 1. 插件化智能体运行时

项目由 Cordis 驱动。

模型、工具、会话、智能体循环、网页服务、文件系统、终端等能力均通过插件组合。

插件可以：

- 注册服务；
- 注册工具；
- 监听运行事件；
- 注入模型上下文；
- 替换能力提供方；
- 按智能体隔离能力；
- 动态挂载和卸载。

因此新增能力通常不需要修改智能体核心循环。

---

### 2. 完整智能体执行链路

一次智能体运行大致经历：

```text
用户输入
  ↓
建立轮次
  ↓
领取输入
  ↓
组装系统提示词和工具定义
  ↓
模型请求
  ↓
模型流式输出
  ↓
工具调用
  ↓
执行工具
  ↓
返回工具结果
  ↓
继续模型推理
  ↓
结束轮次
```

一个轮次可以包含多次模型请求和多次工具调用。

模型能够看到的关键信息会进入会话事件系统，从而支持：

- 会话恢复；
- 历史重建；
- 回放；
- 分叉；
- 状态投影；
- 遥测；
- 图形界面同步。

## 主要能力

### 模型系统

提供统一模型能力接口，并将模型实现与智能体循环解耦。

当前源码包含：

- DeepSeek 模型接入；
- 通用模型适配层；
- 请求重试；
- Token 统计；
- 默认模型选择。

新的模型提供方可以通过适配器接入，而无需修改上层智能体逻辑。

---

### 工具体系

模型可使用的能力统一进入工具注册和执行流水线。

工具执行过程支持：

```text
模型调用工具
   ↓
执行前处理
   ↓
权限 / 策略检查
   ↓
实际执行
   ↓
执行后处理
   ↓
结果写入会话
```

当前代码包含大量现成能力。

#### 文件

- 文件读取；
- 文件写入；
- 字符串替换；
- 文件搜索；
- 文件观察策略；
- 沙箱文件系统。

#### 命令与终端

- Bash；
- PowerShell；
- 持久终端；
- 本地执行；
- 沙箱执行；
- 子进程管理。

#### 开发工具

- LSP；
- 代码执行；
- 工作区操作；
- 文件编辑；
- 运行时诊断。

#### 网络

- 网页抓取；
- 网页搜索；
- DeepSeek 搜索；
- Exa；
- Perplexity。

---

### Code Mode

项目包含独立的代码运行能力。

模型可以通过受控代码运行环境完成较复杂的数据处理或工具组合，而不是将所有操作拆成大量单独工具调用。

代码运行能力与具体执行环境解耦，因此可以使用不同运行后端。

---

### 沙箱

项目将执行环境抽象为独立能力。

目前包含：

- 本地沙箱；
- Linux Landlock；
- Windows ACL；
- E2B；
- 沙箱文件系统；
- 沙箱 Shell。

文件系统、Shell、终端等上层能力可以共同切换到另一套执行环境，而无需分别重写工具。

---

### 会话系统

DeepSeek Harness 将会话视为持久事件流，而不仅是一组聊天消息。

会话能力包括：

- 事件日志；
- JSONL 持久化；
- SQLite 持久化；
- 会话恢复；
- 会话分叉；
- 状态投影；
- 检查点；
- 会话标题；
- 会话统计；
- 遥测；
- 全文查询；
- 会话导出。

这是整个运行时状态恢复和可追踪性的基础。

---

### 子智能体

项目提供完整的子智能体能力体系。

支持的实现包括：

- 当前进程内创建子智能体；
- 独立进程智能体；
- DeepSeek Harness SDK 智能体；
- ACP 智能体；
- Claude Code；
- Codex。

上层只依赖统一的子智能体接口，因此可以替换具体实现。

---

### 工作流与后台任务

项目提供两套长期任务能力。

#### 后台任务

用于：

- 启动任务；
- 查询状态；
- 获取结果；
- 停止任务。

#### 工作流

用于更复杂的多阶段执行过程。

源码包含：

- 工作流定义；
- Worker Thread 执行后端；
- `workflow` 工具；
- `ralph` 工具。

---

### 技能系统

技能能力负责发现和加载可复用的智能体知识与工作方式。

包括：

- 技能注册；
- 本地技能提供方；
- 文件系统技能；
- 技能目录；
- 技能加载工具；
- 图形界面技能展示。

---

### MCP

项目内置 MCP 客户端能力，可将外部 MCP 服务提供的能力接入智能体运行时。

MCP 因此只是整个工具生态的一种接入方式，而不是运行时本身。

---

### 人机协作

智能体运行过程中可以主动与用户协作。

包含：

- 用户确认；
- 权限审批；
- 用户提问；
- 命令系统；
- 计划模式；
- 目标管理；
- 待办事项；
- 消息反馈。

这些能力与模型调用解耦，可以由 Web、命令行或其他客户端呈现。

## 架构原则

理解本项目时，建议记住以下几点。

### 一切能力尽量通过插件提供

新增功能优先寻找已有扩展点，而不是直接修改智能体循环。

### 能力接口与实现分离

一个完整能力通常包括：

```text
能力定义
   ↓
能力实现
   ↓
能力使用方
```

这样才能替换本地、沙箱、远程等不同实现。

### 模型可见信息必须可恢复

只要某条信息最终会进入模型上下文，就应能通过会话记录重建。

### 会话事件是事实来源

界面、恢复、统计、查询等功能尽量由事件日志派生，而不是维护另一套隐藏状态。

### 执行环境应可替换

文件系统、命令执行、终端和开发工具尽量共享统一执行环境，避免每个工具单独实现远程版本。

## 适合做什么

DeepSeek Harness 适合作为：

- 通用智能体运行时；
- 本地编程智能体基础框架；
- 多智能体系统底座；
- 自定义工具型智能体；
- AI 开发工作台；
- 智能体 Web 客户端；
- 自动化任务执行器；
- 智能体协议服务器；
- 智能体架构研究与二次开发基础。

如果你的目标只是调用一次模型接口，这套架构可能显得过重。

如果需要长期会话、工具执行、权限控制、插件扩展、子智能体、沙箱和复杂工作流，它的架构价值才会真正体现出来。
