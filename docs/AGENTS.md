# AGENTS.md — 工作台文档规则

`README.md` 是工作台的主文档，`docs/workbench.zh.md` 是精简技术入口。`docs/` 中其余文档只保留仍能帮助维护当前源码的底层架构、配置、工具、测试、Cordis、子系统和用户参考。

## 保留标准

文档至少满足一项才应长期保留：

- 解释当前仍存在的源码架构或子系统；
- 是当前配置、工具、接口、测试或开发流程的有效参考；
- 是 package / SDK / 用户能力仍需要的使用说明；
- 是生成型参考且仍由当前源码生成或校验；
- 被当前文档门禁、源码说明或维护规则引用；
- 记录仍具有排错价值的底层故障案例。

品牌宣传、已经失效的社区贡献流程、旧 README 翻译对、与当前工作台无关的基准说明不属于保留对象。

## 写作与维护

- 写当前状态，不维护变更流水账；提交历史负责记录“怎么变成这样”。
- 一个事实尽量只有一个权威入口；其他位置使用相对链接。
- 工作台能力、部署、恢复和限制优先更新根 `README.md`。
- 涉及源码内部架构时更新对应底层文档，不把所有实现细节堆进 README。
- 与当前源码冲突的上游文档应修正或删除，不能仅因“原仓库有”而继续保留。
- 链接必须指向实际存在的文件；删除文档时同步检查质量门禁和引用链。
- package README/JSDoc 与代码契约同步更新。

## 仍有价值的主要文档区域

- `architecture.md`：插件与总体架构
- `development.md`：源码开发参考
- `testing.md`：测试体系
- `subsystems/`：各子系统细节
- `cookbook/`：仍适用于当前源码的操作方法
- `cordis-api/`、`cordis-tutorial/`、`cordis-primer.*`：Cordis 机制
- `config-catalog.*`、`tool-catalog.*`、`persistence-catalog.*`、`module-graph.*`：生成/参考目录
- `user/`：当前仍适用的用户、提供方、SDK 指南
- `postmortem/`：底层故障案例与排错参考，不作为现行规范
- `i18n/`：现有双语技术文档的配对与校验规则；当前仓库的文档门禁仍使用它
- `.agents/notes/`：现有技术文档和质量门禁仍引用的设计依据；保留为参考，不要求普通工作台改动新增同类记录

## 工作台验收

文档清理不得删除 `docs/workbench.zh.md` 或让 `scripts/workbench-doctor.mjs` 的必需文件失效。运行源码未变化时不需要为了纯文档清理重建永久产物；若同时修改了应用、包、工作台配置或依赖，则按根 `AGENTS.md` 执行完整构建、doctor 和冷启动验收。
