# 高自由度战争设计原则

本文件是多人模式、地图、经济、AI和胜负规则的上位设计约束。目标是让战争节奏由玩家和战场状态产生，而不是由系统时钟推动。

## 1. 核心原则

### 1.1 玩家决定节奏

允许快攻、慢推、科技冲刺、低科技海量部队、远程消耗、海空封锁、围困、龟缩反击、多线作战和长期大战。

系统不得因为比赛已经进行若干分钟而：

- 改变资源产量；
- 增加/减少单位伤害；
- 强制开放科技；
- 提高积分倍率；
- 削弱防守方；
- 强制生成终局单位；
- 让战略设施突然变值钱；
- 自动进入“决战阶段”。

### 1.2 战争状态推动战争

节奏来源于：

- 工业与资源控制；
- 指挥节点；
- 能源；
- 算力；
- 交通与桥梁；
- 后勤覆盖；
- 情报和传感器；
- 海空控制；
- 科技投资；
- 兵力损耗；
- 战略设施控制。

玩家选择扩张，就获得更多产能，同时承担更长防线和后勤成本；玩家选择龟缩，可以获得防守效率，但会自然放弃地图空间和外部资源。

## 2. 合法时间机制

本项目不禁止所有“秒数”。以下属于操作/技术规则，可以存在：

- 单位建造与研究时间；
- 武器装填和技能冷却；
- 占领/修复/部署作业时间；
- 航空整备；
- 重连与服务器超时；
- 投降投票窗口；
- 动画、音频和过场时长。

这些时间描述某个动作需要多久，不负责强迫整个战争进入下一阶段。

## 3. 禁止的节奏器

标准规则禁止：

- X分钟后资源衰减；
- X分钟后战略点收益翻倍；
- X分钟后地图缩圈；
- X分钟后自动加速胜利分；
- X分钟后双方伤害提高；
- 固定比赛时长；
- 以超时作为普通胜负条件；
- 固定“前期/中期/后期”解锁时钟。

自定义房可以通过独立 `ruleset_id` 制作限时娱乐规则，但不得混入标准规则集。

## 4. 战争能力模型

标准模式共享以下抽象状态，用于判断“是否仍有能力继续战争”，不是一个隐藏倒计时：

`WarCapability = Command + Production + Logistics + TerritoryAccess + CombatForce`

每项只表示是否存在有效路径：

- `Command`：至少存在合法战区指挥节点或可建立节点的能力；
- `Production`：至少存在合法生产/重建链；
- `Logistics`：至少存在维持主要部队的保障路径；
- `TerritoryAccess`：仍有合法建设/部署空间；
- `CombatForce`：仍存在能够执行模式目标的部队。

不同模式可以要求不同组合，不允许用单一“血条”替代真实战争状态。

## 5. 动态控制区域

地图使用 `ControlRegion`，而不是为不同模式复制固定胜利圈。

每个区域拥有：

- 领土控制；
- 战略价值；
- 资源/基础设施；
- 交通连接；
- 补给连接；
- 争夺状态；
- 稳定状态。

一个区域达到“稳定控制”依靠状态条件，例如：

- 己方存在合法地面控制力量；
- 区域没有足以争夺的敌军；
- 与己方指挥/补给网络存在合法连接，或已建立本地保障；
- 对应设施已完成占领或清理。

稳定控制不是“站满30秒”这一种唯一形式。

## 6. 动态前线

前线由相邻控制区域边界自动生成。

`FrontEdge = FriendlyStableRegion <-> Enemy/ContestedRegion`

前线可随：

- 突破；
- 包围；
- 两栖登陆；
- 空降破袭；
- 桥梁摧毁；
- 补给切断；
- 区域反攻

发生改变。

前线模式不得规定玩家必须按固定节点顺序推进。

## 7. 自然进攻成本

进攻无需人工惩罚，但天然存在成本：

- 补给线延长；
- 维修和增援距离增加；
- 防空/传感器覆盖可能变薄；
- 交通拥堵；
- 前进部队更容易暴露；
- 新占区域需要守备和保障。

这些成本构成自然翻盘空间，避免“赢一战就永久滚雪球”。

## 8. 自然防守成本

防守同样有自然代价：

- 放弃外部资源；
- 放弃机场/港口/雷达/数据中心；
- 战略纵深缩小；
- 敌方可以选择围困、封锁或转攻其他区域。

如果玩家能够通过高质量防御以小博大，应允许这种打法成立，不人为处罚“龟缩”。

## 9. 科技自由

科技仅由资源、建筑、前置和分叉决定。

允许：

- 快速冲高科技；
- 长期停留T1/T2；
- 跳过部分军种；
- 将高科技投资转换成较少但更先进的部队；
- 以数量压制高科技路线。

不得根据比赛分钟数解锁或锁死科技。

## 10. AI自由边界

AI默认角色是执行者和参谋，不是节奏导演。

默认主动报告：

- 敌军变化；
- 补给压力；
- 战线缺口；
- 侦察发现；
- 资源/能源/算力风险。

“建议总攻”“建议撤退整个战区”“建议升级某条科技”属于战略建议层，默认可关闭，且未经玩家确认不能自动改变大战略。

玩家直接命令永远优先于AI计划。

## 11. 模式差异来源

模式差异来自胜负逻辑和系统复杂度，不来自强制时长：

- 歼灭：摧毁战争组织能力；
- 征服：稳定控制主要战略区域；
- 前线：通过动态战线持续压缩敌方控制空间并击穿其战区体系；
- 战区：完整多域战争能力与战略控制；
- 快速战争：减少准备成本，更快进入完整战争。

## 12. 数据分析原则

仍然记录：对局时长、首次交战时点、科技到达时点、投降时点等数据，但仅用于观察：

- 是否存在长期无有效决策；
- 是否有某套打法过度拖延；
- 是否存在科技/经济死路；
- 服务器容量规划。

不得看到“平均局太长”就直接加入时间惩罚。优先分析地图价值、经济关系、推进成本、信息反馈和胜负状态是否设计不合理。
