# AI 全量自动编程推进模式

## 总体模式

取消“先原型后量产”的串行项目管理。完整游戏骨架、所有系统接口、国家/地图/战役 ID 一次建立；功能以占位 → 可用 → 完整 → 优化 → 正式品质持续替换。

## 代理角色

总控代理：维护任务依赖图、优先级、阻塞、质量状态。

架构代理：模块边界、公共接口、迁移审批。

专项代理：模拟、战斗、机器人、AI 指挥、电脑对手、导航、情报/电子战、空军、海军、轨道、网络、图形、UI、地图、战役、数值、测试、内容。

集成代理：唯一负责跨模块冲突、接口迁移和主线合并。

## 任务图

所有需求拆为有输入、输出、依赖和验收条件的任务。接口定义完成即允许下游并行，不等待完整实现。

## 分支/工作树

每项开发使用独立分支和独立工作树。代理默认只能修改模块所有权目录；跨模块修改提交接口变更请求。

## 自动循环

领取任务 → 读约束 → 实现 → 本地测试 → 静态检查 → 提交 → 自动测试 → 失败定位/修复 → 集成 → 性能/确定性/平衡验证 → 更新文档 → 领取下一任务。

## 自动回退

主线编译失败、启动失败、确定性失败或严重性能回退时自动回滚问题提交，并建立独立修复任务。主分支不得陪同故障停摆。

## AI 修改红线

- 禁止因为测试失败直接重写大模块；先做最小复现与根因修复。
- 禁止为了提高胜率破坏国家玩法差异。
- 禁止自行改变母设计的世界观、四大体系、AI 权限、首发边界。
- 架构大改先更新 ADR/架构文档并经架构代理审批。

## 进度模型

不使用“阶段完成了吗”作为主要状态；跟踪模块完成率、测试通过率、性能状态、未闭环任务、阻塞依赖、正式品质资产覆盖率。

## 代理记忆

每个模块维护 `MODULE.md`/ADR/已知问题记录，使代理后续接管时先读取既有决策，避免重复研究和反复换方案。
