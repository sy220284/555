# 性能、大规模单位与导航

## 1. 性能设计总原则

项目的性能目标不是“高端机器跑满、低配机器降画质保命”，而是从架构、算法、数据结构和内容预算一开始就按**低成本、高并发、正常画质**设计。

冻结原则：

1. **正常画质是基础渲染路径，不是高配特权。**
2. 同一模式下，不同硬件使用相同的权威模拟、AI、单位数量、情报、电子战、机器人和伤害规则。
3. 低配机器不能靠“少算敌人、降低AI、减少机器人、缩地图、降低模拟频率”达标。
4. 性能优化顺序永远是：减少无效工作 → 改算法复杂度 → 数据导向与批处理 → 缓存/增量更新 → 并行化 → 表现批处理；不是先砍体验。
5. 任何降频都必须是设计层固定、多平台一致、确定性可复现的多速率更新，不得根据机器快慢动态改变规则。
6. 高端硬件增加的是超高分辨率、极端特效密度、额外光照精度和更高刷新率；基础战场视觉不能依赖这些能力成立。
7. 性能回归视为架构问题或实现问题，不能默认通过提高硬件门槛解决。

## 2. 体验基线

### 最低目标机

- 现代 4核8线程 CPU
- 16GB 内存
- 4GB 显存
- SSD
- 1080P
- **标准画质**
- 标准1V1完整玩法：300—800活动单位
- 常规目标：60FPS
- 极高密度瞬时交战：1% Low 目标不低于约45FPS

最低目标机仍必须看到完整的核心视觉语言：单位材质、主要阴影、爆炸、炮火、导弹尾迹、天气、建筑受损状态、机器人动画与战术反馈。不能以“低画质模式”作为最低配置默认体验。

### 主流目标机

- 现代 6核12线程
- 16GB 内存
- 8GB 显存
- NVMe SSD
- 1080P / 1440P
- 标准高质量路径
- 800—1500活动单位
- 60FPS稳定目标

### 高端目标

- 8核16线程及以上
- 32GB 内存
- 10—12GB+显存
- 1440P/4K、高刷新率
- 大型团队1500—3000活动单位

高端档只增加锦上添花的表现，不修复基础画质缺失。

## 3. 模拟性能预算

权威模拟固定30Hz，单帧33.33ms。

标准对局：

- 平均模拟耗时 ≤ 10ms
- P95 ≤ 16ms
- P99 ≤ 22ms

大型对局：

- P95 ≤ 24ms
- 禁止持续超过33.33ms

初始预算：

- 实体移动/状态：2.5ms
- 导航：3ms
- AI：2.5ms
- 战斗/弹道：2.5ms
- 感知/战争迷雾/电子战：2ms
- 经济/后勤/脚本/其他：2ms

预算可随实测重分配，但不能通过降低规则精度获取预算。

## 4. 数据导向实体架构

大规模单位不得使用“一个单位一个重对象、每帧完整更新”的传统结构。

权威模拟优先采用连续内存和按组件批处理：

```text
EntityId[]
Position[]
Velocity[]
Health[]
Armor[]
WeaponState[]
SensorState[]
AIState[]
SupplyState[]
```

要求：

- 热数据与冷数据分离。
- 高频字段按结构化数组布局，提升缓存命中和向量化机会。
- 不在高频循环中做动态分配。
- 不让每个单位拥有独立高频虚函数树。
- 对同类型单位按批次更新。
- 稳定ID与运行时索引分离，避免字符串参与热路径。

## 5. 任务系统与并行化

模拟使用任务图而不是单一主线程串行更新。

推荐依赖：

```text
输入命令
→ 移动意图
→ 分区导航/局部避障
→ 空间索引更新
→ 感知/EW候选集
→ 武器/弹道
→ 伤害结算
→ 状态提交
```

可并行部分按地图分区、阵营或实体批次拆分。

原则：

- 禁止依赖线程执行顺序得到结果。
- 并行任务写入局部缓冲区，固定顺序归并。
- 结果排序、事件提交和随机流必须确定性。
- 主线程只做不可避免的同步点和最终状态提交。

## 6. 事件驱动和脏区更新

绝大多数单位在绝大多数时间没有发生有意义变化，因此禁止全局轮询一切。

可事件化：

- 敌人进入/离开传感器范围
- 单位受击
- 目标死亡
- 路径阻断
- 桥梁/建筑状态变化
- 补给状态变化
- 通信/干扰状态变化
- 建造完成
- 科技解锁

区域系统使用脏标记，只更新受影响单元格和关联对象。

例如桥梁被炸毁，只重算与该桥相连的区域图、路径缓存和局部交通流，禁止全图重建。

## 7. 空间索引统一化

感知、电子战、武器目标搜索、局部避障、爆炸范围、补给和AI威胁判断共享统一空间查询基础设施。

推荐双层结构：

```text
大区粗网格
→ 局部细网格 / BVH / 哈希格
```

禁止每个系统各自维护一套全实体扫描。

查询流程：

1. 空间粗筛
2. 阵营/类型位掩码过滤
3. 距离平方过滤
4. 必要时才做精确视线/遮挡/强度计算

## 8. 分层AI

AI成本必须主要随“战斗群和战区数量”增长，而不是随每个实体线性增长。

结构：

```text
战略AI
→ 战区AI
→ 战斗群AI
→ 轻量单位控制器
```

推荐频率：

- 战略AI：1—2Hz
- 战区AI：2—5Hz
- 战斗群AI：5—10Hz
- 单位局部控制：10—15Hz
- 紧急反应：事件触发

单位控制器只处理：当前命令、局部目标、避障、武器使用和安全反应；不得重复进行战略规划。

## 9. 分层导航

禁止每辆单位独立执行全图A*。

导航结构：

```text
战略区域图
→ 交通通道/道路图
→ 战斗群走廊
→ 局部流场/引导场
→ 单位避障与占位
```

关键优化：

- 同一战斗群共享高层路径。
- 相同起终区域缓存路线。
- 路网和桥梁使用图搜索，不扫描完整地形。
- 大编队提前计算通道容量，避免入口拥堵后反复重寻路。
- 局部避障只读取附近单位。
- 导航网格改变采用增量重建。
- 海军、地面、两栖和空中导航使用不同简化层，不强行共用最复杂方案。

## 10. 感知、战争迷雾与电子战

这些系统最容易出现O(N²)，必须从数据结构上杜绝。

设计：

- 地图划分为感知瓦片。
- 雷达/光电/电子侦察生成影响区域，而不是逐单位扫描全图。
- 静态雷达和电子战源预计算基础覆盖模板。
- 移动源只更新跨越的脏瓦片。
- 阵营可见性采用位图/位集批量运算。
- 同一候选集可供雷达、火控、AI威胁判断复用。
- 只有最后一步才做昂贵的视线和遮挡判断。

画面上的战争迷雾属于表现层，权威情报状态由轻量数据维护。

## 11. 战斗、弹道与拦截

逻辑弹道和视觉弹道彻底分离。

模拟只保存决定结果所需的数据：

- 发射者/目标
- 起点/方向/速度或到达时间
- 制导/干扰状态
- 拦截窗口
- 命中/爆炸事件

视觉层可生成完整模型、尾迹、烟雾、火花和碎片，不参与命中判定。

优化：

- 近防炮和高射速武器采用批次/时间窗结算，而不是每发都创建完整复杂对象。
- 远程炮火可用解析轨迹+稀疏采样，画面插值补足。
- 大量同类导弹共享制导阶段逻辑和空间查询。
- 爆炸只查询受影响空间格。

最终视觉仍显示完整战斗，不因逻辑简化而显得“少打了几发”。

## 12. 机器人与无人蜂群

蜂群和机器人不得让高级AI成本按单位数线性爆炸。

- 群体共享任务、路线、目标候选和威胁图。
- 单位只处理局部位置和武器动作。
- 蜂群阵型/搜索采用场函数或分区任务，不让每架无人机独立全局规划。
- 只有与敌军接触的局部分组进入高频战斗状态。
- 算力是玩法资源，与真实CPU负载完全解耦。

## 13. 物理与建筑破坏

权威模拟使用轻量2.5D碰撞和简化代理体。

Chaos等高成本物理只用于视觉：

- 碎片
- 残骸弹跳
- 局部车体反馈
- 装饰物破坏

建筑采用阶段式破坏：

```text
完整 → 重损 → 坍塌 → 废墟
```

权威通行和遮挡只依据阶段状态与简化碰撞代理更新。

## 14. “正常画质”渲染路径

基础画质本身必须低成本且好看，不能把昂贵特性当成“正常画面”的前提。

标准路径：

- 统一物理材质体系，限制每单位材质槽数量。
- 使用纹理图集、纹理数组、共享主材质实例。
- 静态环境使用烘焙/探针/轻量间接光组合，不强依赖实时全局光照。
- 单位和建筑保留动态主阴影，但通过分级阴影代理、阴影缓存和距离预算控制成本。
- 战场关键爆炸、导弹、炮火和天气保持完整；远距离合批而不是直接删除。
- 地形、植被、建筑和同类车辆大量实例化。
- 正常视距下单位轮廓和关键机械动画始终完整可读。
- 1080P标准质量以原生或高质量时域重建为主，不使用明显糊化的激进缩放作为常态。

高端增强路径才增加：

- 更高精度实时全局光照
- 光线追踪
- 更高阴影采样与距离
- 更高体积云/烟雾采样
- 更长时间残骸和弹痕
- 更高反射精度
- 4K超高材质层

这些增强不能决定基础画面是否“像完整游戏”。

## 15. 几何、动画与材质预算

单位资产从制作阶段就按大规模RTS预算设计，而不是制作完成后再强行降级。

建议原则：

- 中距离是主要美术验收距离。
- 轮廓、炮塔、武器、传感器等决定识别度的细节优先。
- 不把看不见的底盘内部、细小螺丝等做成高成本实时几何。
- 机器人共享骨架族和动画模板。
- 同类载具共享材质主模板。
- 动画更新与渲染插值分离，视觉60Hz不意味着骨骼60Hz全量计算。

## 16. 实例化与表现实体

权威实体和表现实体分离。

- 模拟世界存在5000个单位，不代表存在5000个重Actor。
- 近景重要单位可映射高精表现对象。
- 普通单位优先使用轻量实体/实例化表示。
- 视距变化只切换表现代理，不能销毁权威单位状态。
- 同类远景单位按GPU实例化批次提交。

## 17. 内存与显存

16GB系统内存、4GB显存是标准画质可运行的设计约束之一。

措施：

- 区域流送和资产分区。
- 纹理按屏幕占比流送，不一次驻留全部高分辨率mip。
- 多国家共享基础材质、骨架和特效资源。
- 音频流式加载。
- 战斗事件使用对象池。
- 路径、感知和威胁缓存设容量上限和淘汰策略。
- 录像采用命令流+周期压缩快照，禁止全帧状态历史常驻内存。

## 18. 网络与客户端性能

多人采用服务器权威模拟时：

- 客户端不需要运行完整敌方隐藏信息决策。
- 服务器按玩家情报权限发送状态。
- 大量单位使用批量状态增量，不逐Actor复制。
- 网络状态与视觉插值解耦。
- 客户端可在相同规则下以较低CPU成本做预测/插值。

网络优化不能改变可见性和战斗结果。

## 19. 性能测试矩阵

每次核心提交自动运行：

### 最低目标机
- 300单位标准战
- 800单位1V1峰值
- 城市战
- 机器人混编
- 炮兵+防空高弹道

### 主流目标机
- 800/1500单位
- 多AI战区
- 大规模EW/雷达
- 空地混战

### 压力环境
- 3000单位
- 5000单位
- 10000+实体极限

采集：

- 模拟P50/P95/P99
- 主线程/工作线程占用
- 缓存未命中
- AI耗时
- 路径查询次数及缓存命中率
- 空间查询候选数量
- 弹道事件数量
- draw call/实例批次
- GPU帧时间
- 系统内存/显存峰值
- 网络增量大小

## 20. 性能回归裁决

发现回归后必须先定位是哪种问题：

1. 算法复杂度增长
2. 重复工作
3. 缓存失效
4. 数据布局恶化
5. 锁/线程同步
6. 资产预算超标
7. 批处理失效
8. 表现代理错误升级

只有证明上述路径全部不可行，才能提出设计预算修改；提高最低配置不是默认解决方案。

## 21. 最终验收

性能验收不是“能启动”，而是：

> 4核8线程、16GB、4GB显存、SSD的最低目标机，在1080P标准画质下完成标准1V1全流程，核心画面保持完整，常规目标60FPS，极端瞬时交战仍保持可流畅操作；AI、机器人、电子战、情报、单位数量与高端机器规则一致。

主流6核12线程、16GB、8GB显存平台必须在1080P/1440P标准高质量路径下稳定60FPS，并作为持续集成性能门禁的首要基准之一。
