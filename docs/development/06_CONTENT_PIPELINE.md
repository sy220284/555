# 内容生产管线

## 1. 单位

玩法定位 → 稳定ID → 白盒配置/占位模型 → `UNIT_LOADOUTS.md`装配 → 数值与反制测试 → 概念 → 模型/材质 → 动画 → VFX/音频 → 可读性测试 → 最终平衡。

禁止“先做漂亮模型，再决定单位用来干嘛”。

每个单位进入 `playable` 前必须存在：生产建筑、科技前置、武器/能力、AI角色、音频配置和测试配置。

## 2. 建筑

功能与依赖 → 稳定ID → 占地/建造关系 → 白盒 → 正常视距可读性 → 概念/模型 → 破坏阶段 → VFX/音效 → 平衡。

建筑功能不得由模型名称决定，权威玩法数据独立存在。

## 3. 地图

流程：

```text
MAP_SPECS设计意图
→ 创建 <MAP_ID>.map.json
→ Schema/坐标/资源/道路检查
→ 确定性灰盒生成
→ AI导航与1000场公平测试
→ 出生/资源/路线修正
→ 美术/地形/建筑
→ 破坏/天气
→ 再次AI+真人验证
→ 排位门禁
```

16张地图从一开始全部建立 `layout_defined`，但只有存在合法侧车数据并通过基础门禁才可标记 `graybox_ready`。

## 4. 战役

24关全部先建立可通关灰盒：目标、触发器、AI、增援、胜负、占位对白。

缺省字段遵循 `CAMPAIGN_NARRATIVE_CAST.md` 的初始部队、AI姿态和增援默认契约。

剧情/配音/过场允许在逻辑灰盒之后替换，但必须在 `content_complete` 前全部完成；过场跳过不得影响任务状态。

每关至少突出一个主要玩法，不连续复制“造基地→摧毁基地”。

## 5. 美术资产

概念 → 高模 → 游戏模型 → 材质 → LOD → 动画/挂点 → VFX → 技术验收。

自动检查：三角形、材质槽、贴图尺寸、碰撞、LOD、骨骼、命名、引用、显存预算。

## 6. 机器人复用

建立四足、人形、多足、履带无人平台等基础骨架，国家通过外形、模块、材质和动作风格区分，避免每个机器人重复整套动画。

## 7. 音效/语音

流程以 `specs/AUDIO_VOICE_PIPELINE.md` 为准：

```text
规格/事件ID
→ 音频资产任务
→ AI生成/正版库/实录/程序合成候选
→ 自动质检
→ 人工/音频代理筛选
→ 分层编辑
→ 48kHz/24bit WAV母版
→ 来源/许可记录
→ FMOD事件
→ WarAudioDirector场景验收
```

核心角色正式版优先真人配音；普通单位/系统语音可使用有明确商业授权的合成语音。

禁止未经授权克隆现实人物或演员声线。

## 8. 音乐

AI可用于风格探索、草稿和分轨辅助；正式阵营主题、主菜单和剧情关键主题需经过人工作曲/音频总监定稿。

动态音乐按 `PEACE/BUILDUP/RECON/SKIRMISH/BATTLE/CRISIS/ENDGAME` 等状态分层，不以随机整曲切换作为唯一方案。

## 9. 本地化

文本源使用本地化键。翻译 → 术语一致性 → UI长度 → 字幕时码 → 语音匹配 → 游戏内验证。

关键任务信息不能只存在于语音。

## 10. 资产来源与法务

所有第三方/生成式资产必须记录：来源、作者/服务、许可证、生成模型/版本（适用）、提示词/任务ID（适用）、可商业使用范围、修改记录。

未取得相关商业IP授权时，受保护名称、角色、音乐和美术必须在发行构建前替换为原创内容。

## 11. 占位原则

任何正式资产缺失都使用明显占位，不得阻塞程序、数值、地图或战役测试。

但必须区分状态：

- 占位可跑 = `placeholder/playable`
- 正式资产齐备 = `content_complete`
- 全部门禁通过 = `ship_ready`

禁止把占位资产冒充正式完成。
