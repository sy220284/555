# 全量并行执行模型

## 从第一天存在的内容

4 基础体系、15 国数据骨架、5 级科技、16 张多人图、24 个战役任务、所有核心建筑 ID、所有单位/能力槽位、三种复杂度规则均一次建立。

## 状态模型

每项内容只允许：待处理、开发中、待集成、测试失败、需要重构、完成。禁止使用“基本完成”。

## 动态优先级

P0：阻塞主线/构建/确定性；P1：核心可玩性；P2：完整系统；P3：内容完善；P4：视觉打磨。总控 AI 根据阻塞关系动态调整，不按固定月份串行推进。

## 模块所有权

同一核心模块同时最多 2—4 个编码代理，避免冲突；地图、战役、配置、测试等内容任务可高并发。

## 接口优先

功能第一交付是输入/输出/状态/事件/错误语义。下游在接口稳定后即可用占位实现并行开发。

## 主线要求

任意一天都应可启动并打一局基础对战。大重构通过兼容层/迁移逐步替换，不允许主线数周不可用。

## 交付闭环

代码/数据 + 测试 + 集成 + 确定性 + 性能 + 文档 + AI 可用性/反制 = 完成。

## 人工保留的最终权限

产品裁决（好不好玩）、创意裁决（是否符合世界与阵营）、视觉裁决、发布裁决。编码、回归、数据统计、平衡模拟、文档同步尽量自动化。
