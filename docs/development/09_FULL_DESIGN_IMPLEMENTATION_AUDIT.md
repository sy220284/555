# 全设计深化与实现审计

本文件记录对产品、玩法、内容、技术和生产链的整轮复核。目标不是继续堆设定，而是确保每个核心设计都进入“规格 -> 权威数据 -> 代码边界 -> 自动测试 -> 性能/可玩性门禁”的实现链。

## 1. 总结

当前设计主轴成立：基地建设即时战略 + 现代多域战争 + AI指挥减负 + 无人/机器人/EW + 高自由度战争 + 地图/矿产/科技联动。

本轮最大问题不是缺创意，而是此前仓库只有文档，没有可编译工程、机器可读数据和持续集成。该问题已经开始修复：Unity工程骨架、核心程序集、权威数据、Schema、内容验证器和自动门禁已实际进入仓库。

生命周期统一改为：

`design_defined -> data_defined -> code_contract_ready -> prototype_playable -> validated -> content_complete -> ship_ready`

任何系统没有进入至少 `data_defined + code_contract_ready`，不得再称为“已落地”。

## 2. 产品与模式

### 结论

五种模式保留：歼灭、征服、前线、战区战争、快速战争。它们已经通过开局战备、资源压力、科技状态、地图结构和AI职责形成真正差异。

### 深化

原“经典/现代/战区模式”改称“规则深度预设”，避免与五种游戏模式重名。机器可读值固定：

- `SIMPLIFIED`
- `MODERN_STANDARD`
- `FULL_WAR`

规则深度只控制系统启用范围，不改变基础胜负算法，也不得引入时间导演。

### 实现

`/Data/Rulesets/rulesets.json` 已建立五套标准规则集，并写死 `time_driven_progression=false`。快速战争 `all_tech_granted=true`；征服 `material_tech_binding=true`。

## 3. 经济、矿产与科技

### 结论

资源层保持少数主资源池，地图层使用具体矿种。征服模式独享矿产—科技绑定；其他标准模式不硬锁科技。

### 深化

通用科技材料绑定密度控制：T1/T2不绑定，T3仅1—2项，T4仅2—3项，T5仅1—2项。绑定必须是横向路线选择，不能形成“拿到一种矿，全军全面变强”的垂直雪球。

### 实现

- `/Data/Minerals/minerals.json`：7类矿产/回收资源；
- `/Data/Technology/common_technology.json`：首批通用科技权威数据；
- `/Data/Schemas/minerals.schema.json`、`technology.schema.json`；
- 内容验证器检查征服绑定密度和快速战争全科技规则。

## 4. 单位、建筑、战斗

### 结论

单位/建筑体系已经具备足够规格，但正式实现必须避免“一个单位=复杂GameObject+独立Update”。

### 深化

战斗热状态只保留位置、速度、朝向、生命、装甲、武器、传感、补给、命令等最小数据；表现、美术、语音全部冷分离。

### 实现

- `ModernRA.Simulation` 已有权威热状态组件；
- `ModernRA.Combat` 已建立装甲、武器和伤害事件契约；
- 后续伤害解析必须批量处理 `DamageEvent`，禁止表现层反写伤害。

## 5. AI指挥

### 结论

AI是产品核心卖点，但最大风险是越权和“替玩家玩”。

### 深化

权限固定为战术辅助、战斗群、战区、副指挥四层。每个AI任务都必须同时携带：授权等级、所属玩家、授权区域、禁令和玩家覆盖代次。

### 实现

`ModernRA.AI` 已建立 `AIAuthority`、`AIForbiddenAction`、`AIOrderGeneration` 和更新节拍契约。后续系统必须通过这些字段判权，禁止把权限只写在UI。

## 6. 导航与动态前线

### 结论

动态前线成立，但底层必须避免每单位全图寻路。

### 深化

导航继续使用：区域图 -> 战斗群路径走廊 -> 局部流场/路径 -> 空间哈希避障。桥梁/道路破坏只使局部版本失效。

### 实现

`ModernRA.Navigation` 已建立导航层、路径走廊、目标和局部避障状态。下一门禁是 `MAP_GRAY_RANGE` 区域图和1000单位共享路径压力测试。

## 7. 情报、电子战与网络战

### 结论

体系合理，但不能把EW做成万能控制技能，也不能让客户端持有隐藏真相。

### 深化

内部情报六级保留；EW只修改传感、链路、目标质量和自主能力，不直接修改普通武器基础伤害。

### 实现

`ModernRA.IntelEW` 已建立六级 `IntelLevel`、四级 `EWLevel`、签名和干扰状态。网络层后续只根据服务器授权后的情报等级复制对应精度。

## 8. 机器人

### 结论

机器人必须是“规模/自主/算力”的新体系，不得成为更强的普通坦克。

### 深化

A1—A4保持，通信断联和算力不足只降级自主，不直接让单位消失。机器人始终受资源、电力、算力、指挥容量和维修链共同约束。

### 实现

`ModernRA.Robotics` 已建立自主等级、链路状态、算力申请/授予契约。

## 9. 海空与轨道

### 结论

空海系统继续作为主战域；轨道保持战略层，不发展第二套太空RTS。

### 深化

后续实现优先把机场/港口/补给节点做成真实持续能力约束，再增加高阶平台。轨道首批只做侦察、通信、导航、预警和干扰，不先做复杂轨道机动模拟。

### 实现门禁

空海轨道代码包在模拟基础稳定后接入；不得先制作大量资产再补规则。

## 10. 地图

### 结论

16张地图设计足够，当前真正缺的是16份精确 `.map.json` 和灰盒生成结果。

### 深化

地图完成度不再按文字描述判断。每张图必须经过：Schema -> 区域图 -> 资源/矿产 -> 道路/桥梁 -> 动态前线 -> AI可达 -> 模式兼容 -> 1000场换边公平测试。

### 实现门禁

首张只做 `MAP_GRAY_RANGE`，完成后把生成器和验证器复用于其余15图，禁止16图人工各写一套逻辑。

## 11. 战役

### 结论

24关数量足够，不再扩张。重点转向每章引入一个真实系统并成为教学/叙事一体化载体。

### 深化

任务状态必须数据化；过场只表现，不成为胜负真相源。每个关键目标必须有状态条件、保存恢复和跳过过场路径。

### 实现门禁

先完成序章第1关全链路灰盒，验证任务状态、存档、AI、音频占位、过场跳过，再批量生成后续任务骨架。

## 12. UI与玩家认知

### 结论

当前系统数量已经达到上限附近，后续重点是减负和信息分层。

### 深化

常驻HUD只显示玩家当下决策需要的信息。矿产具体种类、材料供应、EW、算力和补给优先采用异常提示、地图图层和上下文面板，不新增一排永久资源条。

所有新增系统受 `SYSTEM_COMPLEXITY_BUDGET.md` 约束。

## 13. 音频与语音

### 结论

架构成熟，下一步不是继续设计，而是建立注册表和首批真实资产。

### 实现门禁

先完成一组坦克炮、机器人步态、AI警报和单位确认语音，接入 `AudioEventBus -> WarAudioDirector -> FMOD`，并验证1000单位混战聚类。

## 14. 网络与安全

### 结论

服务器权威方向正确。复制层必须从第一天以战争迷雾为安全边界，而不是最后加反作弊。

### 深化

命令和状态分离；客户端只提交意图。快照按情报可见性、空间和重要度过滤。重连快照和录像也不能泄露隐藏真相。

### 实现

`ModernRA.Network` 已建立命令包头、快照包头和复制可见性契约；后续先实现本机单进程服务器/客户端回环，再上真实传输。

## 15. 技术与性能

### 结论

Unity 6 + DOTS/Burst路线保留。最大的工程风险是同时自研过多核心系统，因此边界固定为“自研战争算法，不重造编辑器、资源、渲染、任务调度和传输基础设施”。

### 已实施

- 编辑器版本锁定 `6000.3.24f1`；
- 非预览核心依赖进入 `Packages/manifest.json`；
- 核心、模拟、战斗、AI、导航、情报/EW、机器人、网络程序集已建；
- 权威tick常量固定30Hz；
- 内容验证CI已建。

### 下一性能门禁

正式美术前先证明1500实体完整规则模拟在目标CPU预算内；若模拟层不达标，禁止通过降低单位数/AI或提高最低配置绕过。

## 16. 内容生产规模

### 结论

15国、24关、16图同时全速生产风险过高。

### 深化

文档可以15国完整，但正式资产采用分层质量门禁：优先完成6国核心可玩集 -> 扩到10国排位集 -> 其余国家达到同一门禁后再进入竞技。共享资产和模块化必须优先于国家独占模型数量。

## 17. 当前阻断项

当前不存在设计方向级 `BLOCKED`，但仍有工程阻断：

1. 尚未用真实Unity编辑器验证当前包和程序集编译；
2. 尚无基础场景和首张地图侧车；
3. 尚无10000 tick状态哈希Runner；
4. 战斗/导航/AI只有代码契约，没有完整系统；
5. 正式内容资产仍未生产。

因此当前项目状态只能标记 `implementation_bootstrap`，不能标记 `playable`。

## 18. 后续主线顺序

不按“文档章节”开发，按风险闭环开发：

1. 工程编译 + 数据CI；
2. 10000 tick确定性SimRunner；
3. MAP_GRAY_RANGE灰盒 + 资源采集；
4. 移动/共享导航；
5. 武器/伤害；
6. 情报/战争迷雾；
7. AI战斗群；
8. 机器人/EW；
9. 服务器回环网络；
10. 第一局完整歼灭灰盒；
11. 征服矿产科技；
12. 前线动态战线；
13. 快速战争满战备；
14. 战区大规模扩展；
15. 正式表现、音频和内容批量生产。

每一步必须有自动测试、性能数据和状态哈希后再扩下一层。
