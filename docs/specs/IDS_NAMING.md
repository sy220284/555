# 稳定 ID 与命名规范

本文件与 `CONTENT_REGISTRY.md` 使用同一套唯一命名规则。若历史文档出现其他前缀，以本文件与注册表为准并立即迁移，禁止并存两套 ID。

## 1. 原则

- 显示名称可本地化、改名；稳定 ID 一经进入正式存档、录像、网络协议或发布内容，不得随意变化。
- 代码、数据、测试、地图、战役、美术挂点、音效事件统一通过稳定 ID 或其生成的强类型句柄关联。
- 禁止同一对象在不同部门使用不同自由文本名称作为运行时键。
- 新增 ID 必须先进入 `CONTENT_REGISTRY.md` 或对应专项注册表，再进入代码和资产。

## 2. 唯一前缀

- 基础体系：`FAC_<名称>`
- 国家：`CTY_<国家>`
- 单位：`UNIT_<阵营或国家>_<用途>`
- 编队模板：`FORM_<阵营或国家>_<用途>`
- 建筑：`BLD_<阵营或国家或COMMON>_<用途>`
- 武器：`WPN_<类别>_<用途>`
- 科技：`TECH_<阵营或国家或COMMON>_<主题>`
- 战略能力：`STRAT_<阵营或国家>_<名称>`
- 普通主动能力：`ABL_<范围>_<名称>`
- 状态效果：`STATUS_<名称>`
- 老练度：`VET_<等级>`
- 剧情角色：`CHAR_<范围>_<名称>`
- 游戏模式：`MODE_<名称>`
- 规则集：`RULESET_<名称>`
- 地图：`MAP_<名称>`
- 任务：`MIS_<两位编号>_<名称>`
- 矿产类型：`MIN_<名称>`
- 材料访问标签：`MAT_<名称>_ACCESS`
- 音效：`SFX_<范围>_<对象>_<事件>_<三位变体>`
- 语音：`VOICE_<语言或阵营>_<角色或兵种>_<事件>_<三位变体>`
- 音乐：`MUSIC_<阵营或场景>_<状态>`
- 界面事件：`UIEV_<名称>`
- 本地化键：`LOC_<域>_<名称>`

`FORM_` 只描述编队/批量生产模板，运行时展开为多个真实 `UNIT_` 实体；禁止给 `FORM_` 自己创建碰撞、HP或单实体网络状态。

`MIN_` 描述地图上可采掘/回收的资源类别；具体矿点实例仍使用自身 `node_id`，并通过 `mineral_id` 引用 `MIN_*`。

`MAT_` 不是货币，也不是地图节点。它表示己方产业链当前是否具备某类战略材料的合法供应访问，用于征服模式的部分高阶科技前置和持续供应判断。

## 3. 禁止继续使用的历史前缀

以下旧格式不得出现在新增内容：

- `FACTION_`
- `COUNTRY_`
- `BLDG_`
- `ABILITY_`（战略能力改用 `STRAT_`，普通能力改用 `ABL_`）
- `MISSION_`

历史内容发现上述前缀时必须迁移，不能通过别名长期兼容。

## 4. 资源引用

资源文件名可以包含可读名称，但运行时引用使用稳定 ID。示例：

```text
UNIT_CN_DRAGON_MBT
  -> WPN_TANK_120
  -> SFX_CN_DRAGON_MBT_FIRE_001
  -> VOICE_CN_ARMOR_ATTACK_001

MAP_GRAY_RANGE resource node
  -> MIN_BASE_METALS

MIN_RARE_EARTHS
  -> MAT_RARE_EARTH_ACCESS
  -> TECH_COMMON_LRAD_ABM (RULESET_CONQUEST_STANDARD)
```

资产数据库负责把稳定 ID 映射到 Unity 资源、FMOD 事件、VFX、模型与本地化键。

## 5. 版本与迁移

- 数据格式采用显式 `schema_version`。
- 网络协议、录像格式、存档格式、音频事件表分别版本化。
- 稳定 ID 必须维护迁移表；删除对象时保留墓碑记录，避免旧存档静默指向新对象。
- CI 强制检查重复 ID、非法前缀、悬空引用与旧前缀残留。
- `MIN_`、`MAT_` 进入正式规则集后同样受稳定 ID 迁移规则约束。
