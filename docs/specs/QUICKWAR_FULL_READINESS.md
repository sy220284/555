# 快速战争满战备执行规格

本文件定义 `MODE_QUICKWAR` / `RULESET_QUICKWAR_STANDARD` 的唯一标准开局状态。

快速战争的含义不是“研究更快”或“生产更快”，而是：**双方在进入 LIVE 前已经完成战争准备，以满科技、完整基地体系和足够编制的现役部队直接进入综合战争。**

## 1. 设计目标

玩家进入快速战争后不需要经历基地从零建设、科技爬升和基础兵力积累。

开局就可以直接进行：

- 装甲突击；
- 炮兵/远程火力；
- 防空与反导；
- 无人机和机器人作战；
- 电子战与网络战；
- 有人/无人航空；
- 海军（地图支持时）；
- AI战斗指挥；
- 轨道/战略支援（地图支持时）；
- 战略能力与反战略能力。

模式仍然没有固定比赛时长；“快速”只表示跳过战争准备期。

## 2. 满科技状态

进入 LIVE 时：

- 本阵营 T1—T5 通用科技全部视为已研究完成；
- 本国家/阵营全部正式注册特色科技视为已研究完成；
- 常规模式用于限制发展路线的高阶专精槽不再限制快速战争开局；
- 所有合法单位、建筑、升级、机器人自主等级、AI指挥等级、电子战、网络战、轨道能力均按地图能力开放；
- 互相逻辑冲突的“工作模式/姿态”不能同时激活，但对应科技本身仍视为已拥有。

快速战争中不存在研究队列。科技建筑仍然存在，因为它们承担算力、情报、轨道、战略能力和被摧毁后的体系退化作用。

科技建筑被摧毁不会让已经获得的科技永久遗忘，但依赖该建筑运行的实时能力会失效或降级，直到重建。

## 3. 完整基地体系

每名玩家开局拥有一个 `QuickWarBasePreset`。凡地图支持且本阵营存在的功能建筑类型，都必须至少有一个可运行实例。

标准基地至少包含：

- 指挥核心/建造核心；
- 步兵生产建筑；
- 车辆生产建筑；
- 机器人/无人地面生产建筑；
- 无人航空/航空生产与整备建筑；
- 雷达/传感器节点；
- 数据中心；
- AI战斗指挥中心；
- 高级算力/战略计算节点；
- 基础能源与高级能源；
- 后勤/维修/补给建筑；
- 中远程防空与基地点防御；
- 电子战/反电子战节点；
- 空天/卫星/轨道支援建筑（地图允许轨道时）；
- 海军基地与海军保障（海图/海陆综合图）；
- 阵营特色功能建筑；
- 已解锁的战略能力/超级武器所需实体节点。

“满建筑”表示**所有功能类型已具备并可运行**，不是在出生区无意义地堆满重复工厂或防御塔。

## 4. 基地冗余与容量

为了保证开局部队能够正常运行：

- 初始电力供给必须达到当前基础负荷的至少125%；
- 初始算力供给必须达到初始AI/机器人需求的至少130%；
- 初始补给容量必须达到初始部队理论满负荷的至少120%；
- 空军机位必须覆盖全部初始有人机，并为轻型无人航空保留不少于20%的余量；
- 海军地图的港口保障必须覆盖全部初始舰艇；
- 初始基地必须存在至少两条不会被单次普通火力事件同时摧毁的关键供电/指挥路径。

这些是开局战备要求，不是永久保护；战争开始后所有节点均可按正常规则被摧毁、切断或重建。

## 5. 战略武器初始状态

战略/超级武器所需建筑已经完成建设，但高价值战略武器不在 LIVE 第一个 tick 直接满充能。

规则：

- 战略节点开局在线；
- 武器使用正常初始充能/冷却规则；
- 资源和目标条件仍需满足；
- 双方采用完全相同的模式规则；
- 不得通过出生位置让某一方在对手获得控制权前被战略能力直接摧毁。

这里的充能属于武器动作规则，不属于推动战争节奏的比赛倒计时。

## 6. 初始现役部队原则

快速战争不是“基地建好了但部队还是从零造”。每名玩家必须以**足够进行立即综合作战的现役编制**进入 LIVE。

标准目标：

`InitialCommandUsage = 0.65—0.70 * EffectiveCommandCap`

即开局约使用65%—70%的有效指挥容量，保留30%—35%用于：

- 战损补充；
- 临时改变军种结构；
- 生产战略单位；
- 根据敌方体系进行针对性调整。

禁止开局直接顶满指挥容量，因为那会剥夺玩家后续组织和转型空间。

## 7. 标准联合编制

每个国家按自身单位目录映射到以下角色。只要该国家拥有此类作战能力，就必须存在至少一个有效编制，而不是只给一两个代表单位。

建议指挥容量占比：

| 作战角色 | 初始编制占比 |
|---|---:|
| 步兵/工程/占领力量 | 10% |
| 侦察/传感/前沿观察 | 5% |
| 主战装甲/机械化 | 23% |
| 火炮/火箭/远程打击 | 10% |
| 防空/反导 | 10% |
| 电子战/网络支援 | 7% |
| 机器人/无人地面 | 10% |
| 无人航空/巡飞体系 | 7% |
| 有人航空/高端无人航空 | 10% |
| 工程/维修/后勤支援 | 8% |

总计100%。国家可以在不破坏克制链的前提下按自身特色上下浮动约30%。

海军地图可从装甲、航空和远程火力份额中合计转出15%—25%给海军/海军航空/无人水面与水下力量。

## 8. “各类兵种足够编制”的最低解释

快速战争初始军队必须满足：

- 每个主要战斗域至少一支可以独立执行任务的战斗群；
- 主战装甲不是2—3辆展示单位，而是可以承担一次正面战斗的完整装甲群；
- 防空必须覆盖初始主要战斗群和基地关键区；
- 火力群必须拥有自己的侦察/目标获取和保护单位；
- 机器人/无人系统必须达到可以独立形成任务群的数量；
- 航空必须拥有至少一个完整制空/打击或多用途中队级游戏编制；
- 工程、维修和后勤不能缺席；
- 国家特色单位至少形成一个有战术意义的分队/战斗群，而不是单件展示品；
- 海军图必须形成可独立作战的水面/水下/无人混合编队。

具体数量不跨国家硬编码，使用 `formation_template` 根据单位指挥占用和国家结构生成，避免重装国家与轻量无人国家被同一辆数强行约束。

## 9. 初始资源与补充能力

开局已有基地和部队不从玩家库存扣除，它们属于规则集授予的战备资产。

LIVE 开始时额外提供战损补充储备：

- `ReserveIndustrial = max(12000, StartingForceIndustrialValue * 0.20)`；
- `ReserveStrategic = max(3000, StartingForceStrategicValue * 0.20)`；
- 战场数据采用本阵营满科技所需的已完成状态，不要求重新刷数据解锁科技；实时情报/能力消耗仍按正常规则。

这样玩家可以补一次明显战损，但不能无限无成本重建整支初始军队。

## 10. AI与自动化

快速战争因为开局就是完整战争体系，因此不再限制玩家AI到L1/L2。

- L1—L4均可用；
- 默认权限仍由玩家设置；
- AI不得擅自使用战略能力、改变总主攻、消耗受保护战略储备；
- 玩家直接命令永远覆盖AI；
- 机器人A1—A4按科技和算力全部可用；
- 后勤可使用自动化，但真实补给节点和容量仍存在并可被打击。

## 11. 海空轨道与地图兼容

快速战争不主动删减完整系统。

- 有海域的地图：海军和海军保障按满战备生成；
- 无海域地图：不生成海军资产，也不为缺失海军补偿额外资源，地图平衡由快速战争地图配置负责；
- 有轨道规则的地图：轨道体系开放；
- 禁止轨道的地图：对应节点不生成或保持不可用；
- 航空、机器人、电子战和AI指挥属于标准快速战争核心，不得因“简化”被关闭。

## 12. 部署阶段

在进入 LIVE 前，玩家可以在自己的 `QuickWarDeploymentZone` 内：

- 调整战斗群编成；
- 指定AI授权区和交战规则；
- 移动可部署单位到合法初始阵位；
- 设置航空/海军任务预案；
- 设置基地电力、算力和防御优先级。

不得越过部署区提前攻击或侦察敌方受保护出生区。

部署结束由玩家准备状态决定，不用固定比赛节奏倒计时强迫开战；线上服务可有纯技术性的最大准备超时。

## 13. 后续生产与重建

进入 LIVE 后：

- 所有单位按正常价格和正常生产时间补充；
- 所有建筑按正常价格和正常建造时间重建/扩建；
- 已拥有科技无需重新研究；
- 被摧毁的功能建筑会让依赖系统实时降级；
- 玩家可以继续扩大指挥容量、算力、电力和工业，但受常规上限和地图资源约束；
- 不存在“快速战争专属生产加速倍率”。

## 14. 胜负

快速战争只改变初始战争准备状态，不创造单独的时间胜利。

地图必须声明使用：

- 歼灭子规则；或
- 征服子规则；或
- 前线子规则。

标准快速战争不设置固定局长、超时加速、缩圈或随时间变化的资源/伤害规则。

## 15. 公平性

同一快速战争规则集下：

- 双方 `StartingForceEquivalentValue` 差异目标<=3%；
- 初始总建筑等价价值差异目标<=3%；
- 初始电力/算力/补给余量按需求比例比较，不按绝对数比较；
- 出生区到第一主要战区的到达时间差异必须通过地图公平门禁；
- 阵营特色允许构成不同，但不能靠某阵营开局多一整套战略资产获得免费优势。

## 16. 数据结构

每个快速战争地图/国家组合必须可解析为：

`QuickWarPreset`：

- `ruleset_id`
- `country_id`
- `map_id`
- `all_tech_unlocked`
- `building_package`
- `starting_formations`
- `starting_command_usage`
- `power_capacity`
- `compute_capacity`
- `supply_capacity`
- `reserve_industrial`
- `reserve_strategic`
- `strategic_weapon_initial_state`
- `ai_permission_defaults`
- `domain_support_flags`
- `content_hash`

同一 `ruleset + country + map + content_hash` 必须生成可复现的初始战备状态。

## 17. 验收

快速战争进入 `LIVE` 前必须自动验证：

- 全部正式科技处于已完成状态；
- 不存在还需要研究才能生产的合法单位；
- 所有功能建筑类型已部署或被地图明确禁用；
- 初始单位占用在有效指挥容量65%—70%；
- 主要军种没有空编；
- 电力>=需求125%；
- 算力>=需求130%；
- 补给>=理论需求120%；
- 航空/海军机位与保障足够；
- AI L1—L4可授权；
- 战略能力不会在首个tick无条件释放；
- 双方起始等价值、公平性和地图可达性通过门禁；
- 录像、重连和服务器恢复能完全复现该初始战备状态。
