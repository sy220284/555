# 存档、网络、录像、模组与编辑器数据规格

本文件的网络部分必须与 `development/03_NETWORK_DETERMINISM.md` 和 `technical/TECH_STACK.md` 一致。正式联网采用**专用服务器权威模拟 + Unity Transport + 自研相关性/快照复制层**，不再采用客户端持有完整隐藏世界的纯锁步同步。

## 1. 版本字段

所有持久数据必须包含：
`format_version`、`game_version`、`content_hash`、`map_id`、`ruleset_id`、`timestamp_utc`、`determinism_seed`、`protocol_version`。

禁止仅依赖文件名判断版本。

## 2. 存档结构

```text
SaveRoot
├─ Header
├─ MatchRules
├─ AuthoritativeState
│  ├─ Entities
│  ├─ Resources
│  ├─ Tech
│  ├─ AIState
│  ├─ IntelFog
│  ├─ EWState
│  ├─ Logistics
│  ├─ Orbital
│  └─ MissionScript
├─ CommandHistoryTail
└─ CosmeticState(optional)
```

必须保存：单位稳定ID/实例ID、位置/朝向、HP、弹药抽象状态、任务、战斗群、AI授权区/预算/姿态、算力、电力、科技分支、资源、补给、情报最后已知、假目标、网络战压力、轨道资产、天气、任务脚本变量。

纯视觉粒子、音频播放位置、非权威残骸动画无需保存，加载后重建。

## 3. 实例 ID

运行期实体ID使用64位无符号整数；高16位可保留世界/分区，低48位为递增或确定性分配。录像/网络中实例ID不得复用，死亡实体保留墓碑索引至安全清理点。

## 4. 存档迁移

只保证最近两个主版本直接迁移。迁移器必须是纯数据变换，不运行完整游戏逻辑。无法迁移时给出明确版本错误，禁止静默丢字段。

## 5. 录像

权威录像保存：初始权威快照、随机种子、规则集、内容哈希、玩家命令、必要AI高层决策事件、权威事件、周期校验哈希。

默认每30秒写一次状态校验点；长录像每5分钟可附带压缩关键快照用于快速拖动。

另允许生成玩家视角录像，仅记录该玩家当时被授权看到的情报状态，避免回放泄露比赛期间不可见数据。

## 6. 正式网络模型

客户端只发送**意图和命令**，服务器验证并在固定30Hz权威模拟中执行。服务器再按情报权限、空间相关性和重要度向各客户端发送可见状态。

客户端命令最低字段：

`player_id, client_tick, command_type, payload, sequence, auth_context, checksum`

服务器必须验证：

- 玩家所有权/联盟权限；
- 单位与建筑是否真实存在；
- 资源/科技/冷却/指挥/算力条件；
- 命令范围与模式规则；
- AI授权边界；
- 战略能力权限；
- 序列与重放攻击。

客户端不得上传单位真实位置、伤害结果或资源结果作为权威真相。

## 7. 状态复制

服务器输出采用批量增量快照，不逐实体逐帧高层远程调用。

复制决策至少考虑：

- 玩家当前情报等级；
- 空间距离与战斗相关性；
- 是否正在交战；
- 实体类型；
- 状态是否变化；
- 战斗群共享字段；
- 带宽预算。

推荐频率：

- 近距离交战单位：高频增量；
- 已知但远距离单位：中低频；
- 静态建筑：事件驱动/低频；
- 未侦察真实敌军、潜艇、隐身单位：0Hz，不发送真实状态；
- 假目标：只发送玩家当前情报系统认为成立的表现状态。

数据格式优先：量化位姿、位字段、基线+增量、批量数组、战斗群共享字段、事件流。

## 8. 输入延迟与预测

客户端允许有限预测：本地选择、命令反馈、镜头/UI、己方单位短时运动表现可预测；权威战斗结果、隐藏情报、资源、科技、伤害与胜负必须以服务器为准。

出现延迟、抖动和丢包时不得改变服务器模拟速度迁就单个玩家。客户端采用插值缓冲、命令确认与必要纠正。

## 9. 状态哈希与可复现

服务器每120 tick生成关键状态哈希，覆盖：实体核心状态、资源、科技、AI任务、随机流位置、胜负相关状态。

同一服务器构建、同一初始快照、同一命令/事件流应重放到一致关键状态哈希。

客户端不需要持有完整隐藏世界，因此不要求客户端与服务器对全部隐藏状态逐tick同哈希。

## 10. 断线重连

服务器保留周期权威快照+之后增量事件/命令流。

流程：

```text
重新认证
→ 校验版本/协议/内容哈希
→ 获取该玩家授权快照
→ 接收快照后的增量
→ 重建客户端表现状态
→ 恢复控制
```

标准比赛目标：断线后60秒内允许重连。重连快照不得泄露该玩家无权获得的隐藏状态。

## 11. 观战

观战者不得参与模拟命令。服务器决定其权限：玩家视角、队伍视角、延迟全图赛事视角、管理员/裁判视角。竞技全图观战默认至少延迟120秒，可由赛事配置调整。

## 12. 模组包

每个包包含：
`manifest.json`、唯一`mod_id`、语义版本、作者、依赖、兼容游戏版本、内容哈希、加载优先级、资产与数据路径。

禁止模组修改排位官方规则集。自定义房所有客户端必须内容哈希一致。

## 13. 数据模式

权威对象源数据采用 JSON + JSON Schema + 稳定ID，构建时编译为确定性/紧凑运行时数据。

单位/武器/科技引用只允许稳定ID。构建器必须拒绝悬空引用、重复ID、循环科技前置、非法数值范围。

## 14. 编辑器权限

地图编辑器：地形、资源、道路、战略设施、天气、出生、AI区域、脚本触发。

单位/武器编辑器：允许自定义数据对象与新ID命名空间，不能覆盖官方ID，除非建立明确总转换模组。

科技树编辑器：可视化前置/分叉，自动检查环。

任务编辑器：状态条件、触发、目标、增援、AI指令、剧情事件、胜败。

AI编辑器可开放效用权重/模板，不允许向联网房间注入本地任意可执行代码。

## 15. 脚本安全

战役/模组脚本运行在能力白名单沙箱：无任意文件系统、网络、进程、系统凭据权限；只通过游戏公开API操作实体与任务。

## 16. 官方/模组隔离

官方排位只加载签名官方模拟数据。检测到非官方影响模拟的数据包时禁用排位。纯视觉客户端模组必须经过白名单字段定义，不能修改碰撞、可见性、动画判定时机、UI隐藏情报等竞技信息。

## 17. 数据热重载

开发模式允许单位/数值热重载；正式对局开始后锁定 `ContentHash`。中途改变配置会破坏录像与可复现性，因此正式比赛禁止。

## 18. 备份与恢复

编辑器每5分钟自动保存增量草稿；正式保存采用临时文件+原子替换。损坏文件保留原副本并提供恢复入口。

## 19. 验收

必须自动覆盖：跨版本迁移、5000单位存档加载、任务脚本恢复、AI授权恢复、1500+实体网络同步、隐藏情报泄露、潜艇/隐身/假目标过滤、丢包/抖动/高延迟、重连、权威录像重放、模组依赖冲突、恶意脚本沙箱、内容哈希不一致拒绝、编辑器崩溃恢复。
