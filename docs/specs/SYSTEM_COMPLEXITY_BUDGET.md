# 系统复杂度预算

目的：阻止单个合理系统叠加后把玩家认知、CPU、网络、界面和资产生产推到不可控状态。

每个新增/重大扩展系统必须同时给出六项预算：玩家操作、界面信息、CPU、网络、AI决策、资产生产。

## 强制规则

- 新增常驻玩家资源条默认禁止；优先后台状态、分组状态或情境提示。
- 新系统若增加一个必须频繁手动操作，必须同时删除/自动化等量低价值操作。
- 标准现代规则下，任意一个单位不允许要求玩家同时维护超过3个高频主动状态。
- 单个系统不得要求每个实体独立全局搜索；必须使用空间索引、共享结果或事件驱动。
- 网络复制只发送玩家有权知道且会影响当前表现/决策的状态。
- 国家特色优先复用通用模型、骨架、动画和系统模块；独占资产只投入可识别核心。
- 模式专属系统不得无条件扩散到其他模式。

## 评审阈值

重大设计变更必须回答：

1. 玩家新增几次高频操作？
2. HUD新增几个常驻元素？
3. 1500实体P95模拟预算增加多少毫秒？
4. 4v4服务器每客户端带宽增加多少？
5. AI新增多少决策分支/感知输入？
6. 新增多少模型、动画、特效、音频和本地化资产？

任何一项无法估算，变更不得直接进入实现主线。

## 现有系统处理

- AI指挥：目标是减少操作，不能产生新的高频管理菜单。
- 矿产：地图可见多矿种，但主资源栏仍保持少量资源池。
- 征服矿产科技：仅征服标准规则启用，不扩散到其他标准模式。
- 轨道：只保留战略选择，不建立第二套微操层。
- 后勤：保持三态，禁止扩成现实弹药型号清单。
- 电子战：以区域/链路状态反馈，避免每单位独立干扰面板。
