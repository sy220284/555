# 编码与工程规范

## 基本原则

清晰、确定、可测试、可分析优先于炫技抽象。热路径避免无必要分配、锁、虚调用、字符串查找和复杂反射。

## 命名

类型 PascalCase，函数 PascalCase/项目统一规则，局部变量 camelCase；稳定内容 ID 使用大写类别前缀，详见 `specs/IDS_NAMING.md`。

## 模拟代码

- 所有时间以 tick/固定时长表示。
- 随机流必须显式传入或从稳定上下文取得。
- 状态变化通过明确命令/系统阶段完成，避免不可追踪副作用。
- 遍历顺序影响结果时必须稳定排序。
- 并行计算若写共享状态，需采用稳定归并阶段。

## 错误处理

数据错误在加载/CI 阶段尽量 fail fast；运行时网络/玩家输入错误使用明确错误码和可恢复路径。禁止吞异常后继续产生错误状态。

## 日志

日志必须带模块、tick、实体/任务 ID（如适用）；禁止热路径海量字符串日志，使用采样或事件环形缓冲。

## 评审

涉及 Simulation、Network、AI 公共接口、序列化 schema 的改动必须额外检查确定性、兼容性和录像影响。
