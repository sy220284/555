# 编码与工程规范

技术选型以 `TECH_STACK.md` 为准。

## 1. 基本原则

清晰、数据导向、可测试、可分析、可性能验证优先于炫技抽象。

正式主语言为 C#；高频模拟优先使用 Entities/DOTS + Burst + Job System。

## 2. 命名

- 类型/公开成员：PascalCase；
- 局部变量/参数：camelCase；
- 私有字段按项目统一规则；
- 稳定内容 ID 使用大写类别前缀，详见 `specs/IDS_NAMING.md`；
- 显示名称和本地化不得作为逻辑键。

## 3. 程序集边界

- 模拟层不得引用 UI、Audio、Camera、Material、VFX 或表现 GameObject；
- Presentation 通过只读展示快照/桥接组件消费模拟状态；
- Tools 可以引用模拟接口，但正式模拟不得引用 Editor 程序集；
- 公共接口变化必须检查网络、录像、存档和数据 Schema 影响。

## 4. Entities / DOTS 规则

普通战争单位不得采用每单位 MonoBehaviour `Update()`。

高频系统要求：

- 优先使用组件数据与 Chunk 批处理；
- 只读取完成当前工作所需组件；
- 避免巨型组件；
- 避免每帧大量 Add/Remove Component 造成结构变更；
- 可用 Enableable Component/状态字段时不要频繁迁移 Archetype；
- 对需要大量生成/销毁的对象使用批处理和池化思路；
- 大量实体查询必须有性能测试。

## 5. Burst 热路径规则

Burst/Job 热路径禁止：

- 托管对象引用；
- 字符串；
- LINQ；
- 反射；
- 装箱；
- GC 分配；
- 非必要异常；
- 无界 Native 容器增长；
- 全局锁；
- 每单位全局查询。

优先：

- `NativeArray`/适合任务的 Native 容器；
- `Unity.Mathematics`；
- 紧凑 ID；
- 批量计算；
- SoA/Chunk 友好布局；
- 明确读写依赖；
- 可向量化循环。

## 6. 模拟代码

- 时间以固定 tick 表示；
- 权威模拟固定 30Hz；
- 随机流显式传入或从稳定上下文取得；
- 经济/伤害/科技等关键状态优先整数或量化值；
- 状态变化通过明确系统阶段/命令完成；
- 并行任务采用固定阶段归并；
- 线程完成顺序不得决定规则结果；
- 同一服务器构建和输入流必须可重放关键状态。

## 7. AI

- 战略/战区/战斗群/单位控制分层；
- 高层 AI 低频运行；
- 单位控制器保持轻量；
- 共享威胁图、路径、目标候选和敌情摘要；
- 禁止100个单位重复计算100份相同战略；
- 运行时竞技战斗不调用外部大语言模型。

## 8. 导航

- 禁止每单位独立全地图 A*；
- 必须通过统一导航/空间接口；
- 路径和流场允许缓存；
- 地形局部改变只使相关缓存失效；
- 局部避障只查询空间邻域；
- 新导航算法必须附带大规模基准。

## 9. 网络

- 客户端不是真实世界状态权威；
- 未侦察敌军真实数据不得为了实现方便发送到客户端；
- 大规模状态使用批量增量、量化和相关性；
- 禁止大量每实体高频 RPC；
- 网络序列化必须有显式协议版本；
- 服务端解析任何客户端数据都必须验证范围和权限。

## 10. 错误处理

- 内容/Schema/稳定 ID 错误优先在加载或 CI 阶段 fail fast；
- 玩家输入/网络错误使用明确错误码和可恢复路径；
- 禁止吞异常后继续写入未知状态；
- Burst 热路径不依赖异常控制流程。

## 11. 日志

日志包含模块、tick、实体/任务 ID（适用时）。

热路径禁止海量格式化字符串日志；使用：

- 采样；
- 计数器；
- 结构化事件；
- 环形缓冲；
- 条件编译调试信息。

## 12. GC 与内存

正式战斗帧的目标是接近零 GC。

任何导致稳定战斗中周期性 GC 的提交必须说明原因并提供基准。

大型临时数据使用池/Native 临时分配策略，并设置容量上限。

## 13. Unity 对象规则

- GameObject/MonoBehaviour 用于表现、编辑器桥接和少量特殊对象；
- 权威单位状态不得只存在 Transform/Animator；
- Animator/VFX/Audio 不得反向驱动伤害或移动真值；
- Addressables 资源加载必须异步；
- 战斗热路径禁止 `Resources.Load`/同步磁盘加载。

## 14. 测试要求

计算公式优先写成可测试纯函数/批处理系统。

关键系统至少覆盖：

- 单元测试；
- 组合测试；
- 无画面模拟；
- 长局回归；
- 性能基准；
- 网络异常；
- 录像重放。

修复 Bug 必须新增回归用例。

## 15. 评审重点

涉及以下内容必须额外评审：

- Simulation 公共状态；
- Entity 组件布局；
- Burst 高频循环；
- Job 依赖；
- Network 协议；
- AI 公共接口；
- 序列化 Schema；
- Addressables 内容版本；
- 引擎/Package 升级。

评审必须同时检查正确性、数据兼容、可复现性、性能和最低目标机预算。
