# 可观测性与持续集成

## 1. 持续集成必跑

每次主分支候选提交至少执行：

- 数据/Schema/稳定ID合法性；
- 禁止旧ID前缀扫描；
- C#编译；
- Burst编译检查；
- 单元/集成测试；
- 无画面模拟回归；
- 网络烟测；
- 录像重放；
- 地图侧车Schema检查；
- 内容引用检查；
- 基础性能烟测；
- 秘密/依赖漏洞/许可证扫描。

主分支不允许红灯长期存在。

## 2. 夜间任务

- AI对战农场；
- 800/1500/3000/5000实体基准；
- 90分钟长稳；
- 机器人/无人机专项；
- 断网/断电/节点失效故障注入；
- 高延迟/抖动/丢包；
- 战争迷雾泄露；
- 100门炮音频压力；
- 后台匹配/结果服务回归。

## 3. 游戏内指标

至少记录：

- 模拟tick耗时P50/P95/P99；
- AI/导航/感知/战斗/EW占比；
- 实体数；
- 路径请求与缓存命中；
- 内存/GC；
- 网络上/下行、快照大小、相关性实体数；
- 状态哈希分叉；
- 音频物理声道、虚拟声道、聚类数；
- 地图/国家/规则集胜率。

## 4. 在线服务指标

- 登录成功率；
- API P95/P99；
- 匹配等待时间；
- 匹配分差；
- 匹配取消率；
- 游戏服分配失败；
- 游戏服崩溃；
- 重连成功率；
- 结果上报失败/重复；
- 区域延迟；
- 版本不兼容率；
- 作弊命令拒绝率。

## 5. 日志结构

所有结构化日志至少包含：

`timestamp, environment, service, version, trace_id, match_id(optional), severity, event_name, payload`

不得把访问令牌、密码、私密聊天、完整个人数据写入普通日志。

## 6. 分布式追踪

后台服务采用OpenTelemetry或等价标准。一次“创建匹配票据 -> 分配服务器 -> 开局 -> 结果上报”应可通过 `trace_id/match_id` 串联。

游戏高频tick不逐实体生成追踪Span，避免可观测性本身造成性能问题。

## 7. 告警

最低告警：

- 登录失败率异常；
- 匹配P95超过目标；
- 服务器分配失败持续升高；
- 游戏服崩溃率异常；
- 结果服务积压；
- 关键数据库/缓存不可用；
- 协议不兼容突增；
- 反作弊拒绝异常激增；
- 模拟P95/内存/带宽超过预算。

告警阈值在生产部署配置中版本化，不硬编码在业务代码。

## 8. 性能回归

关键场景建立基准。P95回退>10%自动标记调查；>20%默认阻止合并，除非性能预算变更经过评审。

报告必须能定位到模块、提交、场景、实体规模和主要耗时项。

## 9. 崩溃与BUG

每个崩溃报告绑定：版本/提交、平台、地图、模式、规则集、最近命令摘要、可用录像/最小存档、性能摘要。

可重现BUG优先输出最小命令流或最小存档。

## 10. 发布健康

候选版本必须冻结：Schema、协议、官方内容哈希、规则集版本、地图池版本。

发布采用区域/比例灰度，健康指标异常时停止新会话并回滚；流程见 `ONLINE_SERVICES_MATCHMAKING_LIVEOPS.md`。

## 11. 数据保留

高频调试遥测短期保存并聚合；长期仅保留业务/平衡/安全真正需要的摘要。隐私和安全日志按 `ONLINE_SECURITY_PRIVACY.md` 管理。
