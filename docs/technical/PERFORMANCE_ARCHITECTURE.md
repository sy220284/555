# 性能架构与算法规范

本文件定义《现代红色警戒》的性能工程基线。目标是：**以 2026 主流游戏电脑作为最低完整体验基线，在标准画质下保持正常战争规模、完整 AI/机器人/EW 与稳定帧率；性能主要通过架构、算法、数据布局、批处理和内容预算获得。**

技术选型以 `TECH_STACK.md` 为准。

## 1. 总体原则

性能不是发布末期优化，而是所有系统的上位设计约束。

任何系统正式实现前必须回答：

- 数据规模上限；
- 算法复杂度随单位数如何增长；
- 哪些结果可以共享；
- 哪些更新可以事件驱动；
- 哪些数据属于热路径；
- 是否存在可避免的 O(N²)；
- 是否产生 GC/热路径分配；
- 是否可 Burst、批处理和并行；
- 是否有最低目标机基准。

未经性能预算的系统不得进入正式实现。

## 2. 总体分层

```text
Unity 6
├─ DOTS / Entities 权威实体数据
├─ Burst + Job System 高频批量计算
├─ ModernRA.Simulation 项目战争核心
│  ├─ 战斗
│  ├─ 经济
│  ├─ 导航
│  ├─ 感知/EW
│  ├─ AI
│  └─ 机器人
│
├─ 表现层
│  ├─ Entities Graphics
│  ├─ GPU批量实例
│  ├─ VFX Graph
│  ├─ UI
│  └─ Audio
│
└─ Unity Transport + 自研RTS复制层
```

权威单位状态与表现对象分离。5000个权威单位不等于5000个复杂 GameObject/MonoBehaviour。

## 3. ECS 数据布局

优先使用 Entities Chunk/Archetype 数据局部性与适合批处理的数据布局。

热数据：

- Position
- Velocity
- Heading
- Health
- CurrentOrder
- TargetIndex
- WeaponCooldown
- SensorFlags
- SupplyState

冷数据：

- 显示名称
- 描述
- 本地化
- 美术资源引用
- 低频统计

要求：

- 高频 System 不访问字符串；
- 高频 System 不创建托管对象；
- Burst 热路径无 GC；
- 运行时 ID 使用紧凑整数/稳定句柄；
- 组件只承载必要状态，禁止“大而全”巨型组件；
- 高频系统按 Chunk/单位类型批处理，减少随机访问和分支。

## 4. Burst 与任务系统

高频计算优先实现为 Burst 可编译 Job/System。

原则：

- Job 产生局部结果缓冲；
- 固定阶段统一归并；
- 线程完成先后不得改变规则结果；
- 随机数按系统/实体/时间片使用显式随机流；
- 不在主线程等待可异步完成的视觉/资源任务；
- 避免过细 Job 导致调度开销反噬。

## 5. 多速率模拟

固定规则示例：

- 权威时间推进/运动积分：30Hz；
- 局部避障：10—20Hz；
- 单位战术控制：10—15Hz；
- 战斗群规划：5—10Hz；
- 战区 AI：2—5Hz；
- 战略 AI：1—2Hz；
- 经济统计：1—5Hz。

关键事件可立即唤醒。更新频率属于规则，不随客户端硬件改变。

## 6. 导航算法

禁止大规模独立全图 A*。

```text
区域连接图
→ 道路/桥梁/山口图
→ 战斗群路径走廊
→ 局部流场/引导向量
→ 单位局部避障
```

原则：

- 高层路径按战斗群共享；
- 路径缓存按区域、通行类别和地形版本索引；
- 地形改变只使相关缓存失效；
- 大型编队考虑道路容量和转弯半径；
- 局部避障只查询空间邻域；
- 成员只处理局部偏移，不重复规划整张地图。

## 7. 统一空间服务

感知、电子战、局部碰撞、目标搜索和 AI 共享统一空间网格/空间哈希。

提供：

- SphereQuery；
- AABBQuery；
- SectorQuery；
- RayCandidateQuery；
- NearestN；
- TileInfluenceQuery。

禁止各系统私自全表扫描。

## 8. 感知与战争迷雾

不允许每个传感器逐一扫描全部目标。

采用：

- 分层空间网格；
- 传感器覆盖瓦片；
- 阵营位集；
- 类别位掩码；
- 增量脏区；
- 稳定覆盖缓存。

大型静态雷达覆盖可预计算；移动目标只查询所在区域相关传感器。昂贵视线检测只对最终候选执行。

## 9. 电子战

EW 与传感器共享影响场：

- 雷达质量；
- 通信质量；
- 导航质量；
- 干扰强度；
- 抗干扰修正。

静态影响缓存；移动干扰源只更新覆盖变化瓦片。单位读取聚合结果后再叠加自身抗性，避免单位×干扰源全组合计算。

## 10. AI 性能

高级决策数量应与战区/战斗群数量相关，不与单位数量一一对应。

```text
StrategicPlanner
→ ZonePlanner
→ BattleGroupController
→ LocalUnitController
```

共享：

- 威胁图；
- 价值图；
- 路径走廊；
- 敌情摘要；
- 火力支援表；
- 后勤状态。

100辆坦克不能重复计算100份战略判断。

## 11. 机器人与蜂群

机器人本地控制保持轻量。

蜂群采用：

- 共享任务区；
- 分区搜索；
- 群组航迹；
- 局部避障；
- 共享目标候选。

只有进入局部交战的成员启用高频武器/避障逻辑。微型蜂群表现优先 GPU 批量化，不为每个可见微型体建立复杂对象。

## 12. 权威战斗与弹道

权威战斗采用自研轻量 2.5D 判定，不依赖完整 PhysX 刚体。

武器使用最便宜且语义正确的算法：

- 直射高速弹：解析射线/稀疏时间采样；
- 炮弹：解析抛物线 + 事件命中；
- 导弹：分段制导状态机；
- 蜂群弹药：群组粗导航 + 终端阶段；
- 近防高射速：时间窗批量结算 + 视觉逐发补足。

视觉弹道独立生成，可比权威弹道更细腻。

## 13. 物理边界

权威层使用简化形状：圆、胶囊、盒、凸多边形近似、高度场。

PhysX/视觉物理只用于：

- 碎片；
- 残骸；
- 装饰碰撞；
- 非权威破坏效果。

建筑破坏由权威状态机决定可通行/遮挡阶段，视觉碎块不能反向改变比赛规则。

## 14. 渲染主路径

采用 URP 标准画质作为第一优先级。

单位表现分层：

- 中近距离：Entities Graphics；
- 超远/超大量同构实体：BatchRendererGroup/间接实例化；
- 特殊剧情/英雄：少量 GameObject；
- 微型无人蜂群：GPU批量表现。

优化原则：

- 共享主材质；
- 严格限制材质槽；
- 纹理数组/图集；
- 实例化；
- 视锥/遮挡剔除；
- 层级细节；
- 动画共享与远距采样降频；
- 阴影缓存/代理；
- VFX Graph GPU 粒子；
- 区域资源流送。

标准画质不依赖光线追踪和最高成本实时 GI。

## 15. 动画

- 炮塔、雷达、传感器优先程序化；
- 大量步兵/机器人共享骨架和动画数据；
- 远距离使用动画实例化/顶点动画/降频采样；
- 只有少量近景特殊单位使用复杂 Animator；
- 动画更新频率和渲染精度可以分层，但不能影响权威单位位置与战斗状态。

## 16. 内容预算

每类资产在制作前领取预算：

- 三角形；
- 材质槽；
- 纹理；
- 骨骼；
- 动画复杂度；
- 阴影等级；
- VFX 发射器；
- 远景代理。

超过预算必须有明确玩法/视觉理由并通过性能评审。

## 17. 内存与流送

16GB 系统内存是最低完整体验约束。

要求：

- 地图区块流送；
- 国家资源按当前对局加载；
- Addressables 异步加载；
- 共享材质/动画；
- 录像命令/事件流化；
- 快照差分与压缩；
- Native 临时数组池化；
- AI图和导航缓存有明确上限；
- 战斗热路径禁止同步磁盘读取。

## 18. 网络性能

大量战争单位通过 Unity Transport 上的自定义批量复制层同步。

采用：

- 情报权限过滤；
- 空间/战斗相关性；
- 实体 ID 压缩；
- 位置/方向量化；
- 字段变化位掩码；
- 稳定状态不发送；
- 不同相关性不同同步频率；
- 周期关键快照；
- 客户端插值。

禁止每个实体高频独立 RPC。

## 19. 代码热路径规范

热路径禁止：

- GC 分配；
- 字符串处理；
- LINQ；
- 反射；
- 全局锁；
- 托管容器；
- 无界容器增长；
- 不必要的大数组排序；
- 每帧组件结构变更风暴；
- 重复坐标转换；
- 可缓存却重复计算的昂贵数学函数。

关键循环必须有微基准测试。

## 20. 批处理与向量化

优先批量：

- 距离平方；
- 生命/状态更新；
- 传感器粗筛；
- 移动积分；
- 状态位检查；
- 同类弹道；
- 威胁/影响场更新。

数据布局必须有利于 Burst/LLVM 自动向量化。

## 21. 性能可观测性

开发 HUD/追踪至少显示：

- Sim ms；
- Job worker utilization；
- AI ms；
- Navigation ms；
- Sensors/EW ms；
- Combat ms；
- Active entities；
- Archetype/Chunk 数；
- Structural changes；
- Active planners；
- Path cache hit；
- Spatial candidates/query；
- Draw calls；
- GPU ms；
- RAM；
- VRAM；
- Network bytes/s。

必须可以把性能追踪与录像时间点关联。

## 22. 自动性能门禁

消费者最低性能节点：

- 6核12线程级 CPU；
- 16GB RAM；
- RTX 3060/4060/5060、RX7600 同级 8GB+ GPU；
- NVMe SSD；
- 1080P 标准画质。

核心场景：

- 800单位标准1V1；
- 1500单位标准现代模式/团队战；
- 机器人密集战；
- 雷达/EW密集战；
- 空军高密度战；
- 近防/导弹密集战；
- 城市建筑破坏。

若提交使 P95 模拟耗时、GPU帧时间、内存、GC、Job等待、带宽或导航明显回退，必须阻断或生成高优先级回归任务。

## 23. 优化裁决顺序

1. 删除重复计算；
2. 改为事件驱动；
3. 降低复杂度；
4. 空间索引收敛候选；
5. 共享/缓存结果；
6. 优化 ECS 数据布局；
7. Burst/批处理/向量化；
8. Job 并行；
9. 优化结构变更；
10. 优化资产预算与 GPU 批次；
11. 优化渲染管线；
12. 全部不足后才允许提出设计预算变更。

默认禁止直接提高最低硬件要求。

## 24. 最终目标

最低目标机必须运行同一套完整战争规则和正常画质；高端硬件只提高视觉精度、刷新率和极端娱乐规模。

核心理念：

> **同一场战争，用更高效的数据结构、更少的重复工作和更合适的算法完成，而不是让玩家用更贵硬件替开发承担优化成本。**
