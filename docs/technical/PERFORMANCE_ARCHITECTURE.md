# 性能架构与算法规范

本文件定义《现代红色警戒》的性能工程基线。目标是：**在主流甚至较低配置上保持正常画质、正常单位规模、完整AI与稳定帧率，性能主要通过架构、算法、数据布局和内容预算获得。**

## 1. 总体原则

性能不是发布末期的优化任务，而是所有系统的上位设计约束。

任何系统在设计时必须回答：

- 数据规模上限是多少？
- 算法复杂度如何随单位数增长？
- 哪些结果可以共享？
- 哪些更新可以事件驱动？
- 哪些数据属于热路径？
- 是否会产生O(N²)行为？
- 是否会在每帧分配内存？
- 是否能够批处理/并行？
- 是否有最低目标机基准测试？

未经性能预算的系统不得进入正式实现。

## 2. 总体分层

```text
权威模拟核心（C++ / 数据导向）
├─ 实体状态
├─ 战斗
├─ 经济
├─ 导航
├─ 感知/EW
├─ AI
└─ 机器人
        ↓
表现桥接层
        ↓
Unreal表现世界
├─ 轻量实体/实例化
├─ 少量高精Actor
├─ Niagara
├─ 动画
├─ UI
└─ 音频
```

核心原则：权威单位状态与表现对象分离。5000个权威单位不等于5000个重Actor。

## 3. 实体数据

采用按组件连续存储，优先SoA或适合批处理的混合布局。

热数据：

- Position
- Velocity
- Heading
- Health
- CurrentOrder
- TargetIndex
- WeaponCooldown
- SensorFlags

冷数据：

- 显示名称
- 描述
- 科技文本
- 资产引用
- 低频统计

要求：

- 热循环不访问字符串。
- 热循环不动态分配。
- 运行时索引使用紧凑整数。
- 删除实体采用延迟回收/稳定句柄，避免频繁搬移造成引用错误。
- 批次按组件掩码或单位类型组织，减少分支。

## 4. 任务系统

采用固定依赖任务图和工作窃取线程池。

原则：

- 模拟逻辑产生局部结果缓冲。
- 固定阶段统一归并。
- 禁止线程竞争决定最终结果。
- 随机数按系统/实体/时间片使用确定性随机流。
- 不在主线程等待可异步完成的资产/视觉任务。

权威模拟并发必须可在单线程模式重放验证。

## 5. 多速率模拟

不是所有系统都需要30Hz复杂计算。

固定规则示例：

- 运动积分：30Hz
- 局部避障：10—20Hz
- 单位战术控制：10—15Hz
- 战斗群规划：5—10Hz
- 战区AI：2—5Hz
- 战略AI：1—2Hz
- 经济统计：1—5Hz

关键事件可立即打断等待周期。

这些频率属于游戏规则的一部分，在所有硬件上保持一致。

## 6. 导航算法

导航必须避免大规模独立全图A*。

层级：

```text
区域连接图
→ 道路/桥梁/通道图
→ 战斗群路径走廊
→ 局部流场/引导向量
→ 单位局部避障
```

算法原则：

- 高层路径共享。
- 路径缓存按起止区域和单位通行类别索引。
- 地形改变仅使相关缓存失效。
- 大型编队预测道路容量和转弯半径。
- 局部避障使用邻域哈希，不遍历全体单位。
- 长距离移动优先保持编队中心路径，成员只计算局部偏移。

## 7. 感知与战争迷雾

禁止每个传感器逐个扫描全部目标。

采用：

- 分层空间网格
- 传感器覆盖瓦片
- 阵营位集
- 目标类别位掩码
- 增量脏区
- 稳定覆盖缓存

大型静态雷达的理论覆盖可预先栅格化；目标移动时只查询所在区域对应的传感器集合。

视线检测只对最终少量候选执行。

## 8. 电子战

电子战与传感器共享影响场系统。

每个区域维护组合后的：

- 雷达质量
- 通信质量
- 导航质量
- 干扰强度
- 抗干扰修正

静态影响使用缓存；移动干扰源只更新覆盖变化的瓦片。

单位读取所在区域的聚合结果，再叠加自身抗性，避免每单位对每干扰源计算。

## 9. AI

AI性能目标：高级决策数量与战区/战斗群数量相关，而不是与单位数量一一对应。

结构：

```text
StrategicPlanner
→ ZonePlanner
→ BattleGroupController
→ LocalUnitController
```

共享：

- 威胁图
- 价值图
- 路径走廊
- 敌情摘要
- 火力支援可用表
- 后勤状态

100辆坦克不重复计算100份“当前战略”。

## 10. 机器人与蜂群

机器人本地控制必须轻量。

蜂群使用：

- 共享任务区
- 分区搜索
- 群组航迹
- 局部避障
- 共享目标候选

只有局部进入交战的成员开启高频武器/避障处理。

## 11. 战斗与弹道

权威弹道按武器类别选择最便宜且语义正确的算法：

- 直射高速弹：解析线/稀疏时间采样
- 炮弹：解析抛物线+事件命中
- 导弹：分段制导状态机
- 蜂群弹药：群组粗导航+局部终端阶段
- 近防高射速：时间窗批量结算+视觉逐发补足

视觉弹道独立生成，可比权威弹道更细腻。

## 12. 空间查询

统一空间服务提供：

- SphereQuery
- AABBQuery
- RayCandidateQuery
- SectorQuery
- NearestN

所有系统必须通过统一查询接口，不允许私自全表扫描。

性能监控必须记录平均候选数量与最坏候选数量。

## 13. 物理

权威模拟使用简化形状：圆、胶囊、盒、凸包近似。

复杂车辆悬挂、碎片、布料、装饰碰撞只属于视觉层。

建筑破坏采用状态机和预制代理；局部视觉物理不能反向决定权威通行结果。

## 14. 渲染主路径

标准画质就是第一优先级路径。

目标：4GB显存平台1080P仍保持完整视觉语言。

措施：

- 限制单位材质槽。
- 共享主材质和参数实例。
- 纹理数组/图集。
- GPU实例化同类单位。
- 视锥/遮挡剔除。
- HLOD/层级细节。
- 中远距离骨骼降频+渲染插值。
- 阴影缓存和代理。
- 粒子GPU化和批处理。
- 区域流送。

基础环境光照不依赖最昂贵实时GI；可使用烘焙、探针、天空光和有限动态灯构建稳定高质量基线。

## 15. 内容预算前置

美术资产必须在制作前领取预算。

每类资产定义：

- 三角形预算
- 材质槽预算
- 纹理预算
- 骨骼数量
- 动画复杂度
- 阴影等级
- 特效发射器数量
- 远景代理

超过预算必须有明确玩法/视觉理由并通过性能评审。

## 16. 内存

16GB系统内存是正式设计约束。

要求：

- 地图区域流送。
- 国家资源按对局需要加载。
- 共享基础材质和动画。
- 录像命令流化。
- 快照差分/压缩。
- 大型临时数组来自帧分配器/池。
- AI图和导航缓存有上限。

## 17. 网络

大量单位状态不得使用逐Actor高频复制。

采用批量增量：

- 实体ID压缩
- 位置量化
- 位掩码字段变化
- 按区域/情报权限筛选
- 稳定状态不发送
- 事件与周期纠偏结合

客户端插值视觉状态，服务器保持权威状态。

## 18. 代码热路径规范

热路径禁止：

- 隐式堆分配
- 字符串拼接
- 反射查询
- 全局锁
- 大量虚调用
- 无界容器增长
- 每帧排序大数组（除非有明确预算）
- 重复坐标变换
- 重复昂贵三角函数（可缓存/近似时）

对关键循环建立微基准测试。

## 19. SIMD与批处理

适合的系统优先批量：

- 距离平方
- 生命/状态更新
- 传感器粗筛
- 简单移动积分
- 状态位检查
- 大量同类弹道

不强求手写汇编，但数据布局必须不给自动向量化制造障碍。

## 20. 性能可观测性

游戏内必须提供开发HUD：

- Sim ms
- AI ms
- Navigation ms
- Sensors/EW ms
- Combat ms
- Active entities
- Active planners
- Path cache hit
- Spatial candidates/query
- Draw calls
- GPU ms
- System memory
- VRAM
- Network bytes/s

支持导出性能追踪并关联录像时间点。

## 21. 自动性能门禁

持续集成必须至少包含：

- 最低目标机/等效性能节点
- 主流目标节点
- 服务器节点

核心场景：

- 800单位标准1V1
- 1500单位团队战
- 机器人密集战
- 雷达/EW密集战
- 空军高密度战
- 近防/导弹密集战
- 城市建筑破坏

如果新提交使P95模拟耗时、GPU帧时间、内存或路径查询明显回退，必须阻断或生成高优先级回归任务。

## 22. 优化裁决顺序

出现性能问题时按以下顺序处理：

1. 删除重复计算
2. 改为事件驱动
3. 降低算法复杂度
4. 收敛候选集
5. 共享/缓存结果
6. 优化数据布局
7. 批处理/SIMD
8. 并行任务
9. 优化资产预算/批次
10. 优化渲染管线
11. 仍不足才讨论游戏设计预算

默认禁止直接提高最低硬件要求。

## 23. 最终目标

这套性能架构追求的不是“低配版和高配版两种游戏”，而是：

> 同一个完整战场、同样的AI和规则、同样清晰的正常画质，在较低配置上通过更高效的代码和算法稳定运行；高端硬件只是把视觉精度、刷新率和极端规模继续向上推。
