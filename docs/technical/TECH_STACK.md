# 最终技术栈与实现基线

本文件冻结《现代红色警戒》的生产级技术选型。若其他文档与本文件冲突，以本文件为技术选型上位依据，先修订文档再编码。

## 1. 最终结论

本项目采用：

**Unity 6 系列生产平台 + DOTS/Entities 数据骨架 + Burst/Job System 高性能计算 + 项目自研战争核心算法 + Unity Transport 上的自定义大规模权威网络同步。**

选择原则：

- 优先保证 2026 主流游戏电脑在标准画质下的完整体验；
- 优先保证 800—1500 活动实体的常规对局和 3000—5000 实体的战区扩展能力；
- 核心性能依靠数据布局、批处理、算法复杂度、并发和复用解决；
- 不用高端画质框架换取不必要的 GPU 成本；
- 不把项目关键能力绑定到实验/预览包；
- 不为了通用框架方便而牺牲战争迷雾、安全、网络压缩、AI 和寻路上限。

## 2. 引擎与版本策略

### 2.1 当前生产基线

- Unity 6.3 LTS 作为当前生产基线；
- Windows 11 x64 为首要客户端开发/验收平台；
- Linux x64 为首要专用服务器平台；
- 正式上线前 12—18 个月冻结最终引擎大版本。

### 2.2 升级策略

- 只评估正式发布/LTS 或 Unity 官方标记为生产可用的版本；
- 新 LTS/Update 版本先进入独立迁移分支；
- 必须通过编译、内容导入、性能、网络、录像、存档、确定性/可复现测试后才能升级；
- 禁止 AI 代理自行升级引擎、包或渲染管线版本。

## 3. 主语言与代码层

### 3.1 主语言

- C# 为主语言；
- Burst 可编译的高频模拟代码优先使用 unmanaged/blittable 数据；
- 不建立独立 C++ 权威战争核心；
- 原生插件仅用于经过性能证明且 C#/Burst 无法合理解决的极少数平台/第三方需求。

### 3.2 模拟程序集

建立独立的 `ModernRA.Simulation` 层，禁止引用摄像机、材质、音频、UI 和表现 GameObject。

模拟层包含：

- 实体状态；
- 战斗；
- 经济与科技；
- AI；
- 导航；
- 情报/雷达；
- 电子战/网络战；
- 机器人；
- 后勤；
- 空海轨道规则。

客户端、专用服务器、无画面测试器、平衡模拟器必须尽量复用同一套模拟代码。

## 4. 大规模实体与计算

### 4.1 Unity Entities / DOTS

正式依赖采用 Unity 6 当前正式发布的 Entities 1.4 系列。

用途：

- 活动单位状态；
- 建筑和投射物的轻量状态；
- 战区/战斗群数据；
- 批处理系统调度；
- Chunk/Archetype 级数据局部性。

禁止：

- 每辆坦克一个复杂 MonoBehaviour；
- 每个机器人独立 `Update()`；
- GameObject/Transform 作为权威战争状态；
- 在高频 System 中处理字符串、托管集合或每帧分配。

### 4.2 Burst / Job System

采用正式 Burst 1.8 系列与 Job System。

Burst 热路径包括：

- 移动积分；
- 空间索引更新；
- 目标候选筛选；
- 伤害/弹道批处理；
- 传感器/电子战批处理；
- 局部避障；
- 威胁场计算；
- 大规模统计。

所有高频任务必须无 GC、可分区、可并行、可性能基准测试。

## 5. 战争核心算法

Unity 提供调度和数据骨架，但以下能力由项目自研：

- 分层 AI；
- 分层寻路与战斗群共享路径；
- 统一空间网格/空间哈希；
- 目标相关性和威胁评估；
- 情报等级与战争迷雾；
- 雷达/传感器与电子战传播；
- 机器人算力与自主等级；
- 轻量战斗碰撞/弹道；
- 大规模网络相关性与快照压缩。

这些模块不得依赖单个第三方插件成为不可替换核心。

## 6. AI 架构

运行时战斗 AI 不使用大语言模型。

固定层级：

```text
战略 AI（1—2Hz）
→ 战区 AI（2—5Hz）
→ 战斗群 AI（5—10Hz）
→ 单位轻量控制（10—15Hz/事件驱动）
```

技术：

- 效用评分；
- 状态机；
- 分层任务规划；
- 黑板/共享战区状态；
- 事件驱动唤醒；
- 战斗群级结果复用。

生成式 AI 仅用于开发辅助：代码、测试、录像分析、关卡初稿、数据检查和内容生产。

## 7. 寻路与移动

不使用“每单位独立全地图 A*”。

正式结构：

```text
战略区域图
→ 道路/桥梁/山口连接图
→ 战斗群共享路径走廊
→ 局部流场/导航场
→ 空间哈希局部避障
```

规则：

- 高层路径按战斗群共享；
- 路径缓存按地形版本号失效；
- 桥梁摧毁、工事、堵塞只更新受影响区域；
- 局部避障低频计算，渲染帧插值；
- 交通拥堵参与区域成本，但不得产生大范围逐单位重规划风暴。

## 8. 权威战斗物理

权威战争判定采用自研轻量 2.5D 战斗物理，不以 PhysX 完整刚体模拟作为伤害真相源。

权威层只处理：

- 量化位置/速度/方向；
- 圆/胶囊/简化多边形占位；
- 射线/线段/高度场遮挡；
- 简化弹道；
- 爆炸区域；
- 装甲方向；
- 地形高度与可通行性。

Unity/PhysX 仅用于：

- 残骸；
- 碎片；
- 装饰碰撞；
- 非权威视觉效果。

逻辑弹道与视觉弹道允许解耦。

## 9. 渲染管线

### 9.1 主渲染管线

采用 URP，不采用 HDRP 作为正式基础。

原因：将 GPU 预算优先留给单位规模、阴影、天气、炮火、无人蜂群、机器人和建筑破坏。

### 9.2 单位表现

组合使用：

- Entities Graphics 1.4 系列：中近距离大多数车辆、机器人、建筑；
- BatchRendererGroup/间接实例化：超远单位、微型无人蜂群、超大批量同构对象；
- 少量 GameObject：英雄、剧情对象、需要复杂交互的特殊单位。

### 9.3 动画

- 车辆炮塔/传感器优先程序化；
- 大量步兵/机器人采用共享骨架、动画实例化、顶点动画或 GPU 友好方案；
- 只有近景/特殊单位使用完整 Animator 复杂状态机；
- 远距离动画降频只影响采样，不改变视觉语义。

### 9.4 高端增强

光线追踪、高精度实时 GI、更长阴影和更高体积采样属于增强项，不进入最低/标准画质核心依赖。

## 10. 特效与着色

- VFX Graph：大规模 GPU 粒子、炮火、烟雾、天气、无人蜂群视觉；
- Shader Graph + 手写 HLSL：常规材质与性能敏感效果；
- 统一主材质族、纹理数组/图集、材质属性块；
- 限制透明过绘和高成本全屏效果；
- 战斗逻辑不得依赖 VFX 粒子对象。

## 11. 网络架构

### 11.1 模式

采用**专用服务器权威模拟**。

客户端发送命令，服务器验证并运行权威 30Hz 模拟；客户端只获得其情报权限允许的世界状态。

### 11.2 传输层

采用 Unity Transport 正式版本作为 UDP/管线传输基础。

### 11.3 复制层

正式项目采用项目自研大规模 RTS 复制层，而不是把全部战争状态绑定到通用高层网络框架。

核心能力：

- 战争迷雾/情报权限过滤；
- 潜艇、隐蔽、假目标的信息隔离；
- 空间相关性；
- 战斗重要度；
- 按实体类别和距离动态同步频率；
- 批量位姿/状态增量；
- 量化与位打包；
- 可靠命令与非可靠高频状态分离；
- 周期关键快照；
- 客户端插值和有限预测。

Netcode for Entities 可用于原型/工具验证，但**不作为不可替换生产核心依赖**，除非后续基准证明其在本项目战争迷雾、带宽和服务器 CPU 目标下优于自研复制层。

## 12. 可复现性与确定性

由于正式联网采用服务器权威，不要求不同客户端独立锁步计算整个隐藏世界。

但模拟必须满足：

- 固定 30Hz；
- 显式随机种子/随机流；
- 经济、伤害、科技、资源等关键状态优先整数/定点/量化；
- 浮点关键路径使用稳定顺序与严格约束；
- 同一服务器构建、同一输入流可重放并达到一致关键状态哈希；
- 并行任务采用固定阶段归并，线程完成顺序不能改变规则结果。

跨架构完全位级浮点一致不是客户端联网前提，但录像、测试和服务器回归必须达到规定的状态一致性。

## 13. 专用服务器

采用 Unity Dedicated Server 正式包/构建目标，主要部署 Linux x64。

服务器不加载客户端级：

- 高分辨率材质；
- VFX；
- 音频；
- 动画表现；
- UI。

服务器保留：模拟、AI、导航、网络、存档、录像、反作弊和必要碰撞/地图数据。

## 14. 数据与内容管线

### 14.1 权威设计源

权威玩法数据采用可审查、可合并、可由 AI 修改的结构化文本：

- JSON + JSON Schema 为首选；
- 稳定 ID 与 `CONTENT_REGISTRY.md` 统一；
- 显示名称和本地化不作为键。

### 14.2 构建期烘焙

构建时将文本数据验证后烘焙为：

- BlobAsset；
- NativeArray 友好的紧凑表；
- 运行时二进制内容包。

正式热路径不解析 JSON。

### 14.3 Unity 资源引用

ScriptableObject 仅用于编辑器桥接/美术资源引用，不作为竞技数值唯一真相源。

## 15. 资源加载

采用 Addressables 正式版本管理异步资源加载和内容依赖。

规则：

- 地图/战区按区域流送；
- 客户端与服务器资源清单分离；
- 关键资源预热；
- 战斗热路径不触发同步磁盘加载；
- 内容包带版本和哈希。

## 16. UI

- UI Toolkit：主菜单、科技树、生产栏、设置、战报、编辑器工具；
- 战场世界标记/上千图标：自定义批量屏幕空间/世界空间覆盖层，不创建上千独立复杂 UI 元素；
- AI 指挥、情报、电子战、后勤、轨道采用数据图层切换；
- UI 不直接读取实体内部结构，通过只读快照/展示模型访问。

## 17. 音频

正式推荐 Wwise 作为大型战场音频中间件：

- 大量声源虚拟化；
- 优先级与距离管理；
- 总线/动态混音；
- 武器辨识；
- 性能分析。

若预算/授权不满足，可保留 Unity 音频作为兼容降级方案，但正式量产前必须完成同场景性能比较后冻结。

## 18. 后台与服务

游戏实时对局与后台业务解耦。

推荐：

- Go：账号适配、房间、匹配、赛事、统计 API；
- PostgreSQL：事务型持久数据；
- Redis/Valkey 类缓存：会话、临时队列、热点数据；
- ClickHouse：大规模对局遥测和平衡分析；
- OpenTelemetry：统一遥测；
- Prometheus + Grafana：服务与比赛服务器监控；
- 对云厂商保持适配层，避免核心逻辑绑定单一托管商。

## 19. 自动测试与模拟农场

构建以下可执行目标：

- `ModernRA.Client`；
- `ModernRA.Server`；
- `ModernRA.SimRunner`；
- `ModernRA.BalanceRunner`；
- `ModernRA.ContentValidator`；
- `ModernRA.ReplayTool`。

其中无画面 Runner 用于：

- AI 对 AI；
- 数值平衡；
- 确定性/可复现回归；
- 寻路压力；
- 机器人压力；
- 网络状态生成测试。

## 20. 版本管理与构建

### 20.1 代码/文档/数据

- GitHub；
- Git LFS 管理大型二进制；
- 大文件启用锁；
- AI 代理使用独立分支/worktree。

如果未来原始 DCC 美术资产达到超大规模、多人锁冲突成为持续问题，可将 `SourceArt` 独立迁移到 Perforce；游戏代码、配置和文档仍以 GitHub 为主。

### 20.2 持续集成

- GitHub Actions；
- Windows/Linux 自托管构建机；
- Unity 命令行批处理构建；
- Unity Accelerator/缓存服务降低重复导入成本；
- 每次合并执行数据验证、编译、单元测试、模拟测试和性能烟测。

## 21. 正式依赖原则

只允许正式发布、生产可用依赖进入主线。

当前核心包系列：

- Unity 6.3 LTS；
- Entities 1.4；
- Entities Graphics 1.4；
- Burst 1.8；
- Unity Transport 正式版；
- Dedicated Server 正式版；
- Addressables 正式版；
- URP 与对应 Unity 6 正式版本。

实验版/预览版默认禁止。升级必须建立迁移分支并完整回归。

## 22. 明确不采用

正式核心不采用：

- Unreal Engine/Mass 作为主技术平台；
- HDRP 作为标准渲染管线；
- 独立 C++ 战争核心；
- 每单位 MonoBehaviour/Update；
- 每单位独立全图寻路；
- PhysX 刚体作为权威战斗真相源；
- 大语言模型实时控制竞技战斗；
- 纯客户端锁步作为联网安全基础；
- 依靠提高最低硬件或明显降低标准画质解决核心性能问题。

## 24. 技术验收

技术选型只有在以下目标同时成立时才视为正确：

- 最低目标机：6核12线程、16GB、8GB显存、NVMe，1080P标准画质；
- 标准现代对局：800—1500有效活动实体，完整AI/机器人/EW/情报规则；
- 常规60FPS目标，高密度瞬时交战仍保持流畅输入；
- 战区模式可以扩展到3000—5000+实体；
- 专用服务器无渲染运行完整权威模拟；
- 低配与高配游戏规则完全一致；
- AI、导航、网络和渲染均有可量化性能预算和持续集成门禁。

若达不到以上目标，优先优化架构、算法、数据布局和资产预算，不先提高最低配置。
